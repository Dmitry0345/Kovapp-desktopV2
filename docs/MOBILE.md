# Мобильная версия (APK) на компьютере

Та же система тестов проверяет мобильную версию Kovapp — приложение для
Android из папки `mobile/` проекта. Все разделы, права ролей, вёрстка и
работа двух пользователей идут через **интерфейс APK**, а шесть разделов
`apk_*` проверяют то, чего у сайта нет: надстройку приложения, кнопку
«Назад», «Загрузки» телефона, собственный канал уведомлений, работу без
связи, запасные пути обработки файлов и симулятор телефона.

## Запуск

| Команда | Что делает |
|---|---|
| `run.cmd mobile` | полный прогон мобильной версии: база и сервер в Docker, как у `run.cmd` |
| `run.cmd mobile apk_push apk_shell` | только указанные разделы |
| `run.cmd mobile-external` | мобильная версия против внешнего сервера из `.env` |

Linux и macOS — `./run.sh mobile …`. Без Docker:
`python main.py --mode external --target apk --sections apk_shell`.

Нужна версия проекта с папкой `mobile/` (от 25.09.2026 и новее): в
`PROJECT_DIR` должны лежать `server`, `web_app` и `mobile`.

## Как это устроено

APK на телефоне показывает те же файлы `web_app`, что и сайт, но из самого
приложения и с надстройкой (`mobile/overlay`): скрипты, связывающие
страницу с Android, и замена текстов «про браузер». Запросы к серверу у
приложения идут на тот же адрес, что у сайта.

Система тестов повторяет это внутри контейнера тестов:

```
Chromium (как Android WebView) ──▶ «телефон» 127.0.0.1 ──▶ сервер Kovapp
  экран Pixel 7 / 320 px / планшет      интерфейс APK          тот же, что у сайта
  строка браузера WebView               + надстройка
                                        + эмулятор Android-части
```

- **Движок.** Android System WebView — это Chromium, поэтому мобильная
  версия проверяется только в нём (`BROWSERS` для неё не действует).
- **Экраны.** Реальные устройства Android из Playwright (размер, плотность
  пикселей, сенсорный экран) — см. `APK_DEVICES`. Там, где тест сайта
  открывает «компьютер», у приложения самый большой экран Android —
  планшет в альбомной ориентации.
- **«Телефон».** Отладочный сервер из проекта (`mobile/tools/devserver.py`)
  отдаёт интерфейс так же, как APK, а роль Android-части играет эмулятор
  моста: запоминает системные уведомления, «Загрузки», сеанс, отвечает на
  разрешения. Адрес `127.0.0.1` браузер считает защищённым, как HTTPS у APK.
- **Скачивание.** В приложении файл уходит в «Загрузки» телефона, а не в
  загрузки браузера. Проверки скачивания (`download_via`) сами берут файл
  оттуда и сверяют размер.
- **Push.** Раздел `push` (Web Push и service worker сайта) для приложения
  пропускается: у APK свой канал уведомлений, его проверяет `apk_push` —
  против настоящего серверного модуля `native_push`.

## Разделы мобильной версии

| Раздел | Что проверяет |
|---|---|
| `apk_shell` | надстройка подключена на всех страницах и больше ничего в них не меняет; каждая правка текста находит свой фрагмент в веб-версии ровно один раз, в «Настройках» нет упоминаний браузера; цвет строки состояния и панели навигации — из темы страницы; «Назад» закрывает верхнее окно, меню, выпадающий список, на экране входа сворачивает приложение; файл целиком попадает в «Загрузки» (и собранный страницей, и прямой ссылкой); при входе телефон получает сеанс, при выходе — токен для отвязки; push на открытой странице — всплывающее, нажатие на уведомление открывает раздел, чужой адрес отбрасывается; системное уведомление передаётся телефону с тем же заголовком, меткой и адресом, что у сайта; приглашение включить уведомления: телефон спрашивает разрешение, «Разрешить» включает |
| `apk_push` | сервер включает уведомления для приложения; уведомление раздела приходит по собственному каналу с получателем и адресом; сообщение чата — участнику, но не автору и не постороннему; телефон без связи получает накопленное при подключении, подтверждённое не повторяется; чужой секрет — отказ; телефон, перешедший к другому сотруднику, теряет прежний секрет; выход отвязывает телефон; контрольное уведомление подтверждается; в симуляторе: свёрнутое приложение — уведомление в шторке, нажатие открывает раздел; закрытое приложение — холодный запуск сразу в нужный раздел |
| `apk_offline` | без связи с сервером приложение открывается (интерфейс внутри APK) на всех экранах; связь пропала и вернулась — приложение переподключается само |
| `apk_fallbacks` | по HTTPS видео, фото и отпечатки обрабатывает сама страница; по HTTP отпечаток выбранного файла считает телефон; по HTTP о сжатии видео спрашивается телефон; фото HEIC, которое браузерный движок не распаковал, сжимает телефон, миниатюру строит код сайта; видео, которое страница сжать не может, сжимает кодек телефона, куски собираются по порядку |
| `apk_sim` | симулятор телефона из проекта: «Домой», «Недавние», закрытие и холодный запуск; «Назад» закрывает окна и окна документов, в начале истории сворачивает; без сети интерфейс остаётся, после — запросы идут и канал переподключается ровно один раз; скачанный файл появляется в «Загрузках» |
| `apk_visual` | каждый раздел для ролей `VISUAL_ROLES` в обеих темах на всех экранах: снимок приложения сравнивается со снимком сайта на том же экране. Снимок делается, когда экран перестал меняться; отличие яркости до `APK_VISUAL_TOLERANCE` не считается (сглаживание); при расхождении снимки сайта, приложения и карта отличий — `screenshots/APKDIFF_*` |

Остальные разделы (`auth`, `shell`, `files`, `device`, `network`,
`ui_rights`, `tasks`, …, `visual`) идут без изменений, но через интерфейс
APK. Слои по умолчанию — `ui,visual,realtime,mobile` (`APK_LAYERS`):
проверки сервера без интерфейса (`api`) у сайта и приложения одинаковы и
выполняются обычным прогоном.

## Результат

Та же папка `logs\<дата_время>_full_apk\`. В `summary.txt` строка
«Версия: мобильная» и строка «Мобильная версия: интерфейс APK с
надстройкой (версия), экраны: …».

## Чего здесь нет

Это не Android, а его браузерный движок. Аппаратное сжатие видео,
камера, энергосбережение прошивок Huawei и Honor, доставка через Google
(FCM) проверяются только на телефоне — список ручных проверок в
`docs/mobile-test-report.md` проекта.

## Если что-то не так

| Признак | Что проверить |
|---|---|
| «Для мобильной версии нужна папка проекта» | `PROJECT_DIR` в `.env` указывает на папку, где лежат `web_app` и `mobile` |
| «нет mobile/tools/devserver.py» | проект старше 25.09.2026 — нужна версия с мобильной версией |
| Все проверки `apk_push` падают на первом шаге | на сервере нет модуля `native_push` (сервер старше мобильной версии) |
| `apk_visual`: расхождения в разделе, где за время прогона меняются данные | при `PARALLEL` > 1 другие исполнители меняют списки; проверка сама переснимает пару, но при частых расхождениях запускайте `apk_visual` отдельно |
| `apk_visual`: на снимке сайта другая тема, чем у приложения | два исполнителя работают под одними учётными записями и переключают друг другу тему (она хранится на сервере): внешний режим с `EXTERNAL_CREATE_ACCOUNTS=0` и `PARALLEL` > 1. Включите создание учётных записей или `PARALLEL=1` |
