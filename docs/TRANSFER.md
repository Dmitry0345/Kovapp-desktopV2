# Передача системы другому человеку

## Что передавать

Одну папку `kovcheg-autotest` в архиве. Перед упаковкой:

1. Удалите содержимое `logs\` — там журналы и снимки ваших прогонов.
2. Решите, передавать ли вместе с ней проект Kovapp в `project\`. Если нет —
   получатель укажет свой путь в `PROJECT_DIR`. Если да — удалите из
   `project\` файл `.env` проекта: в нём настоящие пароли почты и ключ
   подписи токенов, а тестам он не нужен.
3. Очистите в `.env` строки `EXTERNAL_ADMIN_LOGIN` и `EXTERNAL_ADMIN_PASSWORD`:
   в них аварийный вход администратора вашего сервера. Поставьте
   `EXTERNAL_CONFIRM_TEST_SERVER=0`. Пароли полного режима (`FULL_*`,
   `DB_ROOT_PASSWORD`) секретом не являются: они живут только внутри
   одноразовых контейнеров. В `config\server.env` секретов нет — его можно
   оставить.

Удобно так: правой кнопкой по папке → «Отправить» → «Сжатая ZIP-папка».

## Что сказать получателю

1. Установить Docker Desktop по `docs/WINDOWS.md`.
2. Распаковать архив в папку без русских букв и пробелов.
3. Положить проект в `project\` или указать путь в `.env`.
4. Запустить `run.cmd` и через час открыть `logs\...\summary.txt`.

Больше ничего ставить не нужно: Python, браузеры, база данных, почтовый
сервер для писем сброса пароля — всё внутри контейнеров.

## Если получатель без интернета

Соберите образы у себя (`run.cmd build`) и сохраните их в файл:

```
docker save kovcheg-autotest-server kovcheg-autotest-tests mariadb:11.4 -o kovcheg-images.tar
```

Передайте `kovcheg-images.tar` вместе с папкой. Получатель загружает их
командой `docker load -i kovcheg-images.tar` и запускает тесты без
пересборки образов:

```
set SKIP_BUILD=1
run.cmd
```
