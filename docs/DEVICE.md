# Автотесты Kovapp на настоящем Android (Appium)

Всё работает в Docker: база, сервер, сборка приложения, **Appium** и сами тесты.
На компьютере нужны только **Android Studio** (с одним созданным эмулятором) и
**Docker Desktop**. Эмулятор модуль запускает сам.

## Папка

```
F:\kovapp_autotest\
  run.cmd             ← запуск
  .env                ← настройки (менять обычно не нужно)
  project\            ← проект Kovapp: web, android, pc
  keys\               ← google_key и google-services из Firebase
  logs\               ← результаты
  (остальное — сам модуль: docker, tests, kovtest, kovtest_pc, config, tools, docs)
```

## Один раз

1. Распакуйте содержимое архива в `F:\kovapp_autotest` (при обновлении — с заменой файлов). `run.cmd` при запуске пишет версию модуля; если архив случайно распакован во вложенную папку, он скажет об этом и ничего не запустит.
2. Проект Kovapp — в `F:\kovapp_autotest\project` (там должны быть `server`, `web_app`, `mobile`).
3. Файлы Firebase — в `F:\kovapp_autotest\keys`:
   - `google_key` — ключ сервера;
   - `google-services` — файл приложения.
4. Эмулятор — создайте в Android Studio: **Device Manager → + → Pixel 8 →** образ
   с **Google Play**. Запускать не нужно.

## Два прогона: с сервисами Google и без них

У части сотрудников телефоны без сервисов Google (Huawei, Honor): там уведомления идут
через собственный канал приложения, со значком «Kovapp на связи». Чтобы проверять оба
случая:

1. В Android Studio: **Device Manager → + (Create Virtual Device)**:
   - профиль **Small Phone** (720×1280) — заодно проверяется маленький экран;
   - **API: 33 («Tiramisu», Android 13)**; **Services: Android Open Source** — это и есть
     «без сервисов Google»; образ **x86_64** (скачается по кнопке рядом);
   - имя: `Small_Phone_NoGoogle` → **Finish**.

   Почему так: у телефонов без Google (Huawei, Honor) Android обычно старше, а WebView не
   обновляется через Google Play и остаётся старым — эмулятор на Android 13 без Google
   проверяет и это. Если приложение на нём попросит «обновить WebView», возьмите API 34.
   Точное имя эмулятора: `F:\Android\Sdk\emulator\emulator.exe -list-avds`.
2. В `.env`: `DEVICE_AVD_NOGMS=Small_Phone_NoGoogle` (а `DEVICE_AVD` — эмулятор с Google Play).
3. Запуск: `run.cmd device-both` — сначала прогон на эмуляторе с Google, затем без.
   `run.cmd all` запускает вообще всё подряд: сайт, APK на ПК и `device-both`.
   У каждого прогона свой отчёт; в строке «Устройство:» отчёта видно «сервисы Google: есть/нет».

Тесты сами понимают, какой случай: с Google ждут доставку через Google, без постоянного
значка и без окна «работа в фоне»; без Google — собственный канал, значок «Kovapp на связи»,
окно «работа в фоне» (тест разрешает его, как сотрудник) и работающую кнопку «Убрать значок».

## Ручная проверка с готовыми данными

Чтобы самому пощупать приложение и сайт, без тестов:

| Команда | Что запускается |
|---|---|
| `run.cmd demo` | сервер с готовыми данными, сайт на ПК и приложение на эмуляторе с Google |
| `run.cmd demo nogms` | то же на эмуляторе без сервисов Google (`DEVICE_AVD_NOGMS`) — собственный канал уведомлений, значок «Kovapp на связи» |
| `run.cmd demo site` | только сервер и сайт, без эмулятора — быстрее и легче |

Что делает команда: поднимает сервер с чистой базой, заполняет её, собирает APK, ставит его
на эмулятор начисто, связывает с сервером и открывает приложение. Сайт — по адресу
`http://localhost:18000/app/` (порт — `FULL_PUBLISH_PORT` в `.env`). Логины и пароли всех ролей
печатаются в окне и сохраняются в `logs\demo-accounts.txt`. Всё работает, пока вы не нажмёте любую
клавишу в окне команды, — тогда контейнеры и эмулятор останавливаются.

Готовые данные:
- 3 организации и 3 проекта: «Видеонаблюдение ЖК «Северный»» с файлами во всех разделах и складом, «СКУД офиса «Альфа»», «Пожарная сигнализация школы № 123»;
- 6 задач на разных этапах: договор подписан и работа у монтажников, пусконаладка, срочная замена камеры (срок — завтра), закупка, ТО, одна задача в архиве; файлы задачи и этапа;
- групповой чат «Монтаж «Северный»» с перепиской и фото, личные переписки;
- оборудование: одна выдача ждёт подтверждения монтажника, одна подтверждена; выдача со склада проекта;
- шаблон задачи «Видеонаблюдение под ключ», уведомление от директора.

Удобно проверять вдвоём: на эмуляторе — монтажником (`at_worker_mont`), на сайте — руководителем
(`at_head_mont`): задачи, этапы и сообщения появляются у второго сразу.

## Ваш смартфон по USB

`run.cmd demo phone` — то же, что `run.cmd demo`, но приложение ставится на настоящий смартфон:
сервер с готовыми данными работает на ПК, а связь телефона с ним идёт **по USB-кабелю**
(`adb reverse`), без Wi-Fi и без настройки адресов.

Подготовка телефона (один раз):
1. Настройки → О телефоне → 7 раз нажать «Номер сборки» — появится раздел «Для разработчиков».
2. Настройки → Система → Для разработчиков → включить «Отладка по USB» (на Xiaomi — ещё «Установка через USB»).
3. Подключить кабелем, который передаёт данные; на экране телефона отметить «Всегда разрешать с этого компьютера» → «Разрешить».

Что делает команда: собирает приложение, **удаляет с телефона прежний Kovapp** (рабочая и отладочная
сборки подписаны разными ключами), ставит отладочную сборку, связывает её с сервером по кабелю,
открывает приложение и окно журнала видео. Кабель не отключайте, пока проверяете. После нажатия
любой клавиши в окне команды связь снимается, сервер останавливается.

## Журнал видео и проверка входа

- `run.cmd video-log` (эмулятор) или `run.cmd video-log phone` открывает **отдельное окно** журнала приложения:
  `KovVideo` — сжатие видео, `KovappJS` — консоль страницы (ошибки, обрывы связи при отправке), а также аварии Android. Окно ждёт новых строк — это нормально; строки появляются, когда в приложении
  отправляют видео: решение («сжатие на телефоне», «без сжатия — видео уже подходит», «на сервере,
  причина …») и итог («сжато за N с: размер, МБ, кадров, к/с, кодек, скорость»). Кодек `c2.android…`
  или `OMX.google…` — программное сжатие (так на эмуляторе); на телефонах — аппаратное.
  После итога — строка «этапы»: время сжатия по этапам, самый долгий — первым (подготовка, чтение,
  декодирование, отрисовка, кодирование, отправка, прочее). Первый в строке этап — узкое место.
  В `demo` и `demo phone` окно журнала открывается само.
- При выходе из `demo` журнал сервера за сеанс сохраняется в `logs\server-demo.log` — в нём запросы файлов и обложек с ответами сервера.
- `run.cmd notify [роль]` — пока идёт демо, отправляет с ПК проверочное уведомление выбранной роли (по умолчанию `worker_mont` — монтажнику): телефон получает его как настоящее. С сайта то же делает директор: «Уведомления» → «Создать уведомление».
- `run.cmd login-check` — пока идёт демо, проверяет вход каждой роли на сервер ПК тем же путём,
  что браузер: «вход есть» / «сервер не принял пароль» / «сервер не отвечает». Демо делает эту
  проверку само сразу после заполнения данными.

## Два телефона одновременно

`run.cmd device-pair` запускает два эмулятора сразу — `DEVICE_AVD` (Pixel 8) и `DEVICE_AVD_NOGMS`
(или `DEVICE_AVD2`) — и у каждого свой Appium. Проверки `device_live` идут между двумя телефонами:
сообщения, задачи и этапы должны появляться у второго телефона сразу, без обновления.

- Нужно около **16 ГБ** оперативной памяти; память второго эмулятора — `DEVICE2_MEMORY_MB` (по умолчанию 2048).
- Перед запуском закройте Android Studio — она тоже занимает память.
- Без второго эмулятора те же проверки идут в обычном `run.cmd device`: вторым участником там сайт в браузере.

## Проверить только изменённое

Разделы — через пробел после команды, отдельные тесты — настройкой `ONLY` (часть названия теста или
имени его функции; несколько — через запятую). В PowerShell:

```powershell
./run.cmd device device_upload                  # один раздел
$env:ONLY = "big_file_outage"; ./run.cmd device device_upload    # один тест раздела
$env:ONLY = "live_chat,live_task_card"; ./run.cmd device device_live
Remove-Item Env:ONLY                            # вернуть полный прогон
```

Названия разделов — `run.cmd list`. В отчёте частичный прогон отмечен строкой «Отбор тестов (ONLY)».

## Проверить ключи

```
run.cmd keys-check
```

Проверка идёт в Docker, тем же кодом, которым сервер отправляет уведомления:
- `google-services` читается, в нём есть приложение `ru.kovcheg.kovapp`;
- Google принимает `google_key` и выдаёт по нему токен доступа;
- оба файла — от одного проекта Firebase;
- отправка через FCM разрешена: пробное сообщение проходит проверку Google, но никому не доставляется.

## Запуск тестов

```
run.cmd device
```

Что происходит:
1. Находится Android SDK, запускается эмулятор — на отдельных портах 5600/5601, начисто
   (без снимка состояния). Android Studio продолжает работать: к тестовому эмулятору
   подключается только Appium, и связь никто не перехватывает.
2. В Docker: база, сервер (с ключом `google_key`), проверка ключей.
3. В Docker собирается отладочный APK из `project` (значения Firebase — из `google-services`).
4. В Docker запускается Appium, подключается к эмулятору, ставит APK начисто
   (как у нового сотрудника).
5. Тесты. Системной частью телефона управляет Appium (установка, системные окна, шторка,
   «Назад», поворот). Страницей внутри приложения — протокол DevTools WebView напрямую
   (тот же, которым пользуется Chromedriver, но без него и без подбора его версии).
   Нажатия и ввод — настоящие события касания и клавиатуры. У каждого действия есть предел
   по времени — прогон не может «повиснуть».
   Касание делается, когда кнопка перестала двигаться (шторка выехала, окно открылось);
   после ввода тест ждёт, пока откроется клавиатура и страница перестанет сжиматься.
   Длинный текст на телефоне пишется в окне письма во весь экран и подтверждается «Готово» —
   как у сотрудника. Если точку касания закрывает другой элемент, это пишется в `full.log`.
6. Контейнеры убираются, эмулятор для тестов закрывается (оставить открытым:
   `DEVICE_KEEP_EMULATOR=1` в `.env`).

**Первый запуск** скачивает около 4 ГБ и идёт 30–40 минут. Следующие — несколько минут.
Во время прогона не трогайте эмулятор.

Отдельные разделы: `run.cmd device device_push device_app`.

## Результат

`logs\<дата>_full_device\summary.txt` — что прошло, что нет и почему;
`screenshots\` — снимки; `full.log` — подробный журнал; `logs\appium-last.log` и `logs\appium-debug.log` — журналы Appium.

## Что проверяется — и как отражается

Тесты показывают реальное положение дел: настоящий сервер и база, только что
собранное приложение, установленное начисто, настоящие системные окна Android,
настоящая доставка уведомлений. Если проверку выполнить нельзя — она помечается
«пропущено» с причиной, а не «пройдено».

| Раздел | Что |
|---|---|
| `device_check` | эмулятор, установка, приложение на экране, связь с сервером, ключи Firebase, падения |
| `device_app` | вход через экран входа, все разделы (вёрстка на реальном экране), «Назад» (закрывает меню; на первом экране — сворачивает), поворот |
| `device_push` | разрешение через системный запрос; канал: Google — если есть сервисы Google и ключи (тогда окно «работа в фоне» не должно появляться), иначе собственный; сообщение в свёрнутое приложение → шторка → нажатие открывает нужный чат; значок «Kovapp на связи»: при Google нет ни значка, ни настройки «Убрать значок», при собственном канале «Убрать значок» открывает настройки |
| `device_offline` | сервер пропал — интерфейс на месте; вернулся — данные снова идут |
| `device_rights` | меню каждой из 13 ролей такое же, как на сайте |
| `device_tasks` | задачи касаниями: «Новая задача» → форма → «Сохранить» (проверка на сервере); карточка у сотрудника — этапы, описание этапа (окно письма → «Готово») сохраняется само, «Завершить»/«Возобновить этап»; касание строки открывает задачу; удержание выделяет строку → «Изменить» → новое название; «Удалить» → подтверждение → задачи нет ни в списке, ни на сервере |
| `device_projects` | проекты касаниями: «Создать проект» → форма; касание карточки открывает проект, удержание — выделяет; удержание → «Редактировать» → новое название; вкладка «Файлы проекта» → пять разделов видны на экране → «Склад»; удержание → «Удалить» → подтверждение; фильтр «Организация»: поиск в списке и выбор — остаются только её проекты |
| `device_live` | реальное время (WebSocket): сообщение в чате в обе стороны (ровно одна копия), задача из формы на телефоне — сразу в списке у второго участника, описание и завершение этапа — сразу в его карточке, удалённая задача — карточка у него закрывается сама. Второй участник — сайт в браузере (`run.cmd device`) или второй телефон (`run.cmd device-pair`); задержка дольше 3 с — предупреждение, дольше 10 с — ошибка |
| `device_upload` | большой файл (40 МБ, частями) на телефоне: связь телефона с сервером обрывается посреди загрузки и возвращается — загрузка продолжается, файл на сервере совпадает с отправленным по SHA-256; «Отменить» посреди загрузки и во время обрыва — ни плитки, ни записи, ни кусков на сервере |
| `device_final` | итог: приложение не падало за весь прогон (журнал аварий Android) |

Если ключи есть, а приложение выбрало собственный канал, тест покажет ошибку с
текстом из карточки «Это устройство» — почему так вышло.

Если приложение закрылось посреди прогона, следующий тест пишет предупреждение с причиной («оно упало: …») и запускает его заново — одно падение не валит остальные тесты, а итог `device_final` покажет каждое падение целиком.

## Свои тесты

Раздел — файл `tests\device_<имя>.py` и строка в `config\sections.yaml`
(`targets: [device]`). Устройство — `t.world.device`: `login(роль, раздел)`,
`js(...)`, `back()`, `home()`, `open_shade()`, `tap_native([...])`,
`notifications()`, `audit(t, имя)` и др. (см. `kovtest\appium_env.py`).

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| «Не найден Android SDK» | укажите в `.env`: `ANDROID_SDK=F:\Android\Sdk` |
| «Нет эмулятора» | создайте его в Android Studio: Device Manager → + |
| «Appium не может подключиться к эмулятору» | если Windows спрашивала разрешение для PowerShell — разрешите (частные и общедоступные сети) и повторите; журнал — `logs\appium-last.log` |
| на эмуляторе окно «Разрешить отладку по USB?» | нажмите «Разрешить» (с галочкой «Всегда») — один раз |
| чёрный экран эмулятора, «device offline» | закройте эмулятор и запустите снова: он стартует начисто. Если повторяется — уменьшите память эмулятора в `.env`: `DEVICE_MEMORY_MB=2048`, закройте тяжёлые программы |
| «страница приложения не отвечает: поверх приложения открыто окно …» | системное окно Android, которое тест не узнал; название окна — в строке. Пришлите отчёт |
| «FCM: сбой отправки» в журнале сервера, «No address associated with hostname» | контейнеру не ответил DNS. По умолчанию используются 1.1.1.1 и 8.8.8.8; если в вашей сети они закрыты, укажите свои в `.env`: `DOCKER_DNS_1=…`, `DOCKER_DNS_2=…` |
| прогон прервали или закрыли окно | `run.cmd stop` — остановит контейнеры, эмулятор для тестов и вспомогательные процессы |
| в диспетчере задач «Android Studio (4)», «kovapp», «OpenJDK Platform binary» | это сама Android Studio с проектом kovapp и её сборщик Gradle, а не тесты. Закройте Android Studio через File → Exit |
| «страница приложения недоступна тестам: …» | причина — в строке; чаще всего приложение собрано не в отладочном режиме (у него нет отладочного сокета WebView) |
| «Сборка APK не удалась» | строки с ошибкой — в окне выше; пришлите их |
| «Ключи не работают: …» | Google отказал — причина написана в строке; `run.cmd keys-check` — отдельная проверка |
| «Ключи не удалось проверить: нет связи с Google» | это сбой связи из Docker, а не плохие ключи; повторите `run.cmd keys-check` |
| «Appium не открыл сессию: Failure [INSTALL_…]» | Android отказался ставить приложение — код отказа в строке; подробный журнал — `logs\appium-debug.log`. Если эмулятор на самой новой версии Android, создайте второй на Android 15 (API 35, образ Google Play) и укажите его в `.env`: `DEVICE_AVD=имя` |
| в отчёте «Подготовка устройства» / «Сервер не отвечает» | тесты не запускались — причина написана в строке ошибки |
