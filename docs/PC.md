# ПК-версия Kovapp — проверка (`run.cmd pc`)

ПК-версия — программа для Windows на Python и PySide6 (Qt 6, архив `pc.zip`). Её проверка не
использует Docker: программа запускается из исходников тем же Python, что и при сборке
`Kovapp.exe`, а тестовый сервер работает внутри самого прогона. Исключение — показ руками
`demo pc`: он идёт на сервере в Docker, том же, что у `demo web` (ниже).

## Что нужно (один раз)

1. **Python 3.10, 3.11 или 3.12 (64 бита)** с сайта python.org. В установщике отметьте
   «Add python.exe to PATH». Проверка: в PowerShell `py -3 --version` или `python --version`.
2. **ПК-версия в папке `project`**: распакуйте `pc.zip` в `F:\kovapp_autotest\project` —
   получится `project\pc\main.py` (в архиве уже есть папка `pc`). Старое содержимое `project\pc`
   перед этим удалите. Другая папка — `PROJECT_PC_DIR` в `.env`.
3. Интернет — только при первом запуске: библиотеки скачиваются один раз.

`.\run.cmd version` покажет строку «ПК-версия: версия …».

## Запуск

| Команда | Что делает | Время |
|---|---|---|
| `.\run.cmd pc` | всё: без окон, разделы под каждой ролью, действия, мессенджер в обеих темах | 17–22 мин |
| `.\run.cmd pc unit` | только проверки без окон: сжатие, отправка, функции | около 1 мин |
| `.\run.cmd pc sections` | только разделы под каждой ролью | около 11 мин |
| `.\run.cmd pc actions` | только действия директора: тема и размер на ходу, переходы, этап и журнал, шаблоны, загрузки | около 2 мин |
| `.\run.cmd pc messenger` | только мессенджер, светлая и тёмная тема | около 4 мин |
| `.\run.cmd demo pc` | показ руками: сервер в Docker с данными — тот же, что у `demo web`, + окно программы (окно входа) | пока не нажмёте клавишу |
| `.\run.cmd demo pc director` | то же, но вход сразу ролью: ключ из `config\roles.yaml` (director, head_mont, worker_mont, stock, admin, …) или логин | пока не нажмёте клавишу |

Части можно перечислять через пробел: `.\run.cmd pc unit messenger`. ПК-версия входит и в
`.\run.cmd all` — шестой частью.

**Показ руками (`demo pc`).** В отличие от `run.cmd pc` (окна сами открываются, кликать нельзя),
`run.cmd demo pc` поднимает в Docker тот же сервер с готовыми данными, что и `run.cmd demo web`:
3 проекта, 6 задач на разных этапах, чаты, оборудование, склад. Нужен запущенный Docker Desktop —
как для `demo web`. Адрес, логины и пароли — тоже те же: учётные записи всех ролей печатаются в окне
команды и лежат в `logs\demo-accounts.txt`. Затем открывается настоящее приложение из `project\pc`,
настроенное на этот сервер (`http://localhost:18000`, порт — `FULL_PUBLISH_PORT` в `.env`).

Одновременно с программой работает сайт: откройте в браузере `http://localhost:18000/app/` — это тот
же сервер, поэтому сделанное в программе сразу видно на сайте, и наоборот. Можно войти в программе
одной ролью, а в браузере — другой.

`demo pc <роль>` входит сразу этой ролью. Закончили — нажмите любую клавишу в окне команды:
программа закроется, сервер остановится (его данные при этом удаляются, как и у `demo web`). Печать
программы и её ошибки — в `logs\demo-pc.log`, журнал сервера за сеанс — в `logs\server-demo.log`.
Ваши настоящие настройки Kovapp не трогаются. На Linux/macOS — `./run.sh demo pc`.

Ещё одна часть — `compression`: исходники проверки качества сжатия (`logs\compression-inputs`)
сжимает код программы, результат — в `logs\compression-results\ПК`. Отдельно её запускать не нужно:
это делает `.\run.cmd compression` (раздел 6 `docs/RUNNING.md`), он же строит общий отчёт.

Если экран меньше окна снимков (1600×1000 — например, 1920×1080 с масштабом Windows 125 %), окно
уменьшается по экрану, и проверка «карточки настроек видны без прокрутки» становится
предупреждением: на таком экране прокрутка ожидаема.

Что происходит:

1. Первый раз создаётся папка `.venv-pc` — отдельный Python для проверки, и в неё ставятся
   библиотеки из `project\pc\requirements.txt` — те же версии, что для сборки `Kovapp.exe`.
   Дальше это занимает секунды.
2. Окна программы **сами открываются и закрываются** — не трогайте в это время мышь и
   клавиатуру, иначе щелчок может закрыть окно, которое проверяется. Указатель мыши тест
   отводит в угол экрана.
3. Ваши настоящие настройки Kovapp не трогаются: каждый прогон пишет настройки в свою папку.

Сжатие видео проверяется FFmpeg из папки `project\pc\ffmpeg` — тем, что поедет к сотрудникам.

## Что проверяется

| Часть | Проверки |
|---|---|
| `unit` — без окон | **стили для старого веб-движка (Chromium 83):** замены `gap` (с учётом собственных отступов), `:focus-visible`, `inset`, `aspect-ratio`, `:is()`/`:not()`; страница мессенджера собирается для Chromium 83 и 87, в новом движке (у PySide6 — Chromium 134) — без замен; **функции мессенджера:** адреса файлов, группы файлов, порядок, непрочитанные, деление больше 10 файлов; **уведомления:** карточка, звук, системное уведомление при свёрнутом окне, свои и открытый чат — без уведомления, группы, настройки; **фото:** поворот по EXIF, PNG, GIF, WebP, BMP, крупное → WebP 3200, прозрачность; **отпечатки файлов** (как у сайта) на граничных размерах; **gzip** документов; **видео:** состав FFmpeg (OpenH264, AAC, HEVC, AV1/dav1d, VP9) и его лицензия — LGPL, без частей под GPL (x264 нет), 12 образцов → H.264 High + AAC, стороны, ≤30 к/с, звук, длительность, индекс в начале файла; правки (обрезка, поворот, отрезок); обложка; **отправка** на тестовый сервер: группа файлов, ход отправки, видео сжато на компьютере и пришло кусками, документ — gzip, отмена |
| `sections` — разделы под каждой ролью | вход и неверный пароль; пункты меню по правам; переход в каждый раздел и его страницы (уведомления, задачи и архив, задача и её файлы, новая и правка задачи, проекты, проект с разделами и складом, новый проект, организации и карточка, правка организации, оборудование, работники, профили, настройки, файлы CSV, мессенджер, колокольчик); закрытые правами разделы не открываются; склад без доступа — объяснение вместо ведомости; на каждом экране — без ошибок Python, без сбоев запросов и без предупреждений; вёрстка — нижняя панель у нижнего края, текст в выпадающих списках не обрезан; снимок каждого экрана |
| `actions` — действия директора | вход: смена темы на ходу, введённый логин на месте; переходы между разделами — прежний раздел остаётся снимком, пока новый подгружается, и ни одного отдельного (пустого) окна, в том числе при «только заполненных» строках склада и фильтре задач с датами; настройки: тема и размер без перезапуска, круг новой темы от нажатой кнопки, выбор уходит на сервер; подсказки — тёмная плашка со светлым текстом; флажки списка сотрудников — квадрат цвета акцента с белой галочкой; этап задачи — завершение и возобновление на сервере, обе записи в журнале задачи; шаблоны задач — создание, изменение, удаление сохраняются, затемнение после вложенного окна уходит; загрузки — готовое исчезает само, ошибка остаётся, крестик убирает завершённые, новое скачивание без прежних строк; медиаконтент проекта — только фото и видео (окно выбора и перенос файла); оборудование — кнопка снимка внутри рамки; просмотр — счётчик «1 из 2» текстом, без подложки |
| `messenger` — светлая и тёмная тема | список, лента, меню, эмодзи, поиск; окна: выбор сотрудника (один, с кем чат есть — неактивны), вложения группы по размеру списка, название группы, правка фото и обрезка видео по центру главного окна; работа: текст, реакция, правка, удаление, четыре файла одним сообщением (фото до 300 КБ как есть, крупное — WebP, видео сжато с правками, смета gzip) с проверкой файлов на сервере, пересылка, группа (создание, участники, переименование, удаление), входящее сообщение (карточка, открытие чата), переход из мессенджера в мессенджер |

Роли по умолчанию: директор, администратор, руководитель монтажного отдела, инженер
проектного отдела, монтажник, кладовщик, бухгалтер — у каждой свой набор прав (меню, проекты,
склад, CSV). Разделы директора проверяются в обеих темах. Свой набор — командой из папки модуля:
`.venv-pc\Scripts\python kovtest_pc\run_pc.py --roles director,to,contract --dark-roles director,head`
(ключи ролей — `kovtest_pc\mock\mock_server.py`, список `PEOPLE`).

## Тестовый сервер

`kovtest_pc\mock` — сервер в памяти, отвечающий в тех же форматах, что настоящий
(`server_app`): сотрудники всех ролей, задачи, проекты, склад, оборудование, организации,
уведомления, мессенджер с живой перепиской, загрузка файлов кусками и сокет событий. Логику
настоящего сервера (права, базу, обработку файлов) проверяет прогон веб-версии; здесь
проверяется сама программа.

## Где результат

`logs\<дата_время>-pc\`:

| Файл | Что в нём |
|---|---|
| `summary.txt` | открывать первым: процент успешных проверок, таблица по прогонам, все ошибки и предупреждения |
| `index.html` | снимки всех экранов по прогонам — для просмотра глазами; ошибки — рядом |
| `full.log` | всё подряд: вывод и журнал каждого прогона (шаги, проверки, запросы с ошибкой) |
| `results.json` | все проверки для программ |
| `<прогон>\shots\*.png`, `<прогон>\run.log` | снимки и журнал одного прогона |

Хранятся последние `KEEP_RUNS` прогонов ПК-версии (как и остальных, по умолчанию 30); рабочие файлы проверок
без окон (сжатые видео) удаляются, если ошибок не было.

Код завершения: `0` — всё прошло; `1` — нет Python или ПК-версии; `2` — неизвестная часть;
`3` — библиотеки не установились; другой — есть ошибки (подробности в `summary.txt`).

## Если что-то не так

| Признак | Что делать |
|---|---|
| «Не найден Python» | установить Python 3.10–3.12 (64 бита) с python.org, отметив «Add python.exe to PATH», и открыть новое окно PowerShell |
| «Библиотеки не установились» | нужен интернет; если Python был 32-битный или 3.13+ — поставить 3.12 (64 бита), удалить папку `.venv-pc` и запустить снова |
| «Нет ПК-версии в папке …» | распаковать `pc.zip` в `project` (получится `project\pc\main.py`) |
| `demo pc`: «Docker не найден» или «Docker Desktop не запущен» | показ руками идёт на сервере в Docker, как `demo web`: запустить Docker Desktop (`docs\WINDOWS.md`) |
| `demo pc`: сервер готов, а окна программы нет | причина — в `logs\demo-pc.log`; сайт `http://localhost:18000/app/` при этом работает |
| прогон «не завершился» | подробности — в `full.log`; чаще всего окно закрыли щелчком во время прогона |
| нужно начать с чистого Python | удалить папку `.venv-pc` — она создастся заново |

На Linux и macOS — `./run.sh pc`. FFmpeg в `pc.zip` — для Windows, поэтому там нужны свои
`ffmpeg` и `ffprobe` с OpenH264 (папка с ними — в `KOVAPP_FFMPEG_DIR`). Пакет `ffmpeg` из Debian и
Ubuntu собран с x264 и без OpenH264 — такой проверку состава не пройдёт; подходящий собирает
`tools/ffmpeg/build_ffmpeg.sh linux` из `pc.zip` (README ПК-версии, «Как пересобрать FFmpeg»).
На Linux без экрана нужен `xvfb`.
