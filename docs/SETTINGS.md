# Параметры файла .env

## Режим

| Параметр | Значение по умолчанию | Что задаёт |
|---|---|---|
| `RUN_MODE` | `full` | режим, если его не указали в команде: `full` или `external` |
| `TARGET` | `web` | что проверять: `web` — сайт, `apk` — мобильную версию (`run.cmd mobile` задаёт сам) |

## Полный режим: сервер внутри Docker

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `PROJECT_DIR` | `./project` | папка проекта Kovapp (где лежат `server` и `web_app`); можно абсолютный путь `C:/Projects/kovcheg` |
| `FULL_ADMIN_LOGIN`, `FULL_ADMIN_PASSWORD` | `admin`, `Admin-Autotest-2026` | администратор тестовой базы |
| `FULL_ACCOUNT_PASSWORD` | `Autotest-2026!` | пароль всех тестовых ролей |
| `FULL_JWT_SECRET` | тестовый ключ | секрет подписи токенов тестового сервера |
| `FULL_FILE_ACCESS_STRICT` | `1` | строгий режим доступа к файлам на тестовом сервере |
| `FULL_PROJECT_ACCESS_MODE` | `open` | режим видимости проектов (`open` или `strict`) |
| `FULL_PUBLISH_PORT` | `18000` | порт, на котором сервер виден с вашего компьютера при `run.cmd server` |
| `DB_ROOT_PASSWORD` | тестовый | пароль базы MariaDB внутри контейнера |

База создаётся заново при каждом прогоне и живёт только в памяти
контейнера — прогоны не влияют друг на друга.

## Настройки сервера в Docker: `config\server.env`

Сюда перенесены из рабочего `.env` проекта настройки, от которых зависит
поведение сервера: срок входа, правила пароля и кода сброса, запрет страницы
`/docs`, CORS, параметры перекодирования видео, сжатие, журналы. Сервер в
Docker получает их при каждом запуске, поэтому ведёт себя так же, как рабочий.
Если на рабочем сервере что-то из этого поменяется — поправьте ту же строку
здесь.

Часть настроек тестовая система задаёт сама, и в `server.env` они не
действуют, даже если их туда вписать:

| Настройка | Почему своя |
|---|---|
| `JWT_SECRET_KEY` | ключ рабочего сервера не должен покидать его: кто знает ключ, может войти под любым сотрудником |
| `DB_*` | у тестов своя одноразовая база в контейнере |
| `MAIL_*` | письма уходят во внутренний почтовый ящик контейнера, откуда тесты читают код сброса пароля; через настоящий Gmail письма ушли бы на несуществующие адреса тестовых учётных записей |
| `RESET_REQUEST_COOLDOWN_SEC` | `0`: иначе тест сброса пароля ждал бы минуту между запросами кода |
| `BACKUP_*`, `BINLOG_*`, `WATCHDOG_*` | выключены: одноразовую базу не нужно копировать, а утилит резервного копирования в контейнере нет |
| `ADMIN_FALLBACK_ENABLED` | `0`: аварийный вход в тестовом сервере не нужен |
| `SERVER_*`, `WEB_APP_DIR`, `FILE_STORAGE_ROOT`, `LOG_DIR` | пути и порт внутри контейнера |
| `PROJECT_ACCESS_MODE`, `FILE_ACCESS_STRICT` | задаются параметрами `FULL_PROJECT_ACCESS_MODE` и `FULL_FILE_ACCESS_STRICT` в `.env` |

## Внешний режим

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `EXTERNAL_BASE_URL` | — | адрес сервера, например `http://83.171.90.230:54545` |
| `APP_PATH` | `/app/` | путь веб-приложения на сервере |
| `EXTERNAL_ADMIN_LOGIN`, `EXTERNAL_ADMIN_PASSWORD` | — | учётная запись директора или администратора |
| `EXTERNAL_CONFIRM_TEST_SERVER` | `0` | подтверждение, что сервер тестовый; без `1` внешний режим не запустится |
| `EXTERNAL_CREATE_ACCOUNTS` | `1` | создать на время прогона 12 временных учётных записей ролей (фамилия «Автотест») и удалить после |
| `EXTERNAL_ACCOUNT_PASSWORD` | — | пароль временных учётных записей |
| `EXTERNAL_CLEANUP` | `1` | удалить после прогона созданные тестами задачи, проекты, организации, шаблоны, оборудование и группы |
| `EXTERNAL_FILE_ACCESS_STRICT` | `auto` | какой режим доступа к файлам ожидать; `auto` — узнать у сервера |
| `ROLE_<РОЛЬ>_LOGIN`, `ROLE_<РОЛЬ>_PASSWORD` | — | готовые учётные записи ролей, если `EXTERNAL_CREATE_ACCOUNTS=0` (например `ROLE_HEAD_MONT_LOGIN`) |

## Браузеры

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `BROWSERS` | `chrome,firefox,webkit` | в каких браузерах проверять интерфейс: `chrome` — Google Chrome (воспроизводит видео H.264), `chromium` — встроенный Chromium, `firefox` — Firefox, `webkit` — движок Safari. Первый в списке — основной: в нём идут проверки прав и остальные тесты без перебора браузеров. Для быстрого прогона оставьте один |
| `MOBILE_DEVICE_WEBKIT` | `iPhone 13` | телефон для мобильной версии в WebKit — как Safari на iPhone |
| `TREAT_AS_SECURE` | `1` | разрешить Chromium считать тестовый сервер защищённым: без HTTPS браузер не даёт сжимать видео на устройстве, и проверялся бы только запасной путь сервера |
| `HEADLESS` | `1` | `0` — показывать окна браузеров (только при запуске без Docker) |
| `DESKTOP_VIEWPORT` | `1440x900` | размер окна компьютерной версии |
| `MOBILE_DEVICE` | `Pixel 7` | телефон для мобильной версии (любое устройство Playwright, например `iPhone 13`) |
| `THEMES` | `light,dark` | темы оформления |
| `DEVICES` | `desktop,mobile` | размеры экрана |
| `TIMEOUT_MS` | `15000` | сколько ждать элемент на странице |
| `SLOW_MO_MS` | `0` | замедление каждого действия в браузере |
| `RECORD_VIDEO` | `0` | `1` — записывать видео каждой браузерной проверки в папку прогона |

## Скорость

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `PARALLEL` | `1` | сколько исполнителей работают одновременно (до 8). Каждый — со своими учётными записями ролей и своими данными, поэтому друг другу не мешают. Тяжёлые разделы (`visual`, `network`, `ui_rights`) делятся между исполнителями на части, разделы с общими настройками сервера (`permissions`, `warehouse`) идут в одном исполнителе. Для i7 7-го поколения и 16 ГБ памяти — `3` (подробности в `docs/WINDOWS.md`) |

## Что проверять

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `SECTIONS` | `all` | разделы, если их не указали в команде |
| `LAYERS` | `api,ui,visual,realtime` | слои проверок |
| `VISUAL_ROLES` | из `config\ui.yaml` | роли для проверки вёрстки разделов |
| `CRAWLER_ROLES` | из `config\ui.yaml` | роли для обхода кнопок |
| `REALTIME_TIMEOUT_S` | `12` | сколько секунд ждать появления изменения у второго пользователя |
| `NETWORK_SHORT_OUTAGE_S` | `6` | длительность короткого обрыва сети во время отправки большого файла |
| `NETWORK_LONG_OUTAGE_S` | `90` | длительность долгого обрыва: дольше самой длинной паузы между повторами клиента (30 с) |
| `NETWORK_UPLOAD_DELAY_MS` | `1200` | искусственная задержка каждой порции, чтобы обрыв пришёлся на середину отправки даже в быстрой сети |
| `NETWORK_FILE_MB` | `40` | размер файла для проверки обрыва; больше 32 МБ, чтобы он шёл частями |
| `NETWORK_OFFLINE_EXPECT` | `resume` | что ждать, когда сеть устройства пропала на несколько секунд: `resume` — отправка продолжается после возвращения сети; `abort` — прерывается с предупреждением |
| `PUSH_DEVICE_LOGIN`, `PUSH_DEVICE_PASSWORD` | — | учётная запись, под которой вы вошли в Kovapp на своих телефонах и Mac с включёнными уведомлениями; по ней проверяется доставка на настоящие устройства |
| `PUSH_DEVICE_WAIT_S` | `60` | сколько секунд ждать подтверждения от устройств |
| `NETWORK_OFFLINE_GRACE_S` | `120` | сколько приложение ждёт пропавшую сеть или сервер, прежде чем отменить отправку; должно совпадать с `OFFLINE_GRACE_MS` и `STALL_MS` в клиенте |
| `TOUCH_MIN_PX` | `24` | меньше — ошибка «слишком мелкий для нажатия» |
| `TOUCH_WARN_PX` | `40` | меньше на телефоне — предупреждение «мелковат для пальца» |

## Мобильная версия

Действуют при `run.cmd mobile` и `run.cmd mobile-external` (подробно — `docs/MOBILE.md`).

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `APK_DEVICES` | `mobile,small,tablet` | экраны приложения: `mobile`, `small`, `tablet` или название устройства Playwright |
| `APK_PHONE` | `Pixel 7` | телефон для `mobile` (412 px) |
| `APK_SMALL` | `Galaxy S9+` | самый узкий экран для `small` (320 px) |
| `APK_TABLET` | `Galaxy Tab S4` | планшет для `tablet` |
| `APK_WIDE` | `Galaxy Tab S4 landscape` | экран, который у приложения заменяет «компьютер» в тестах |
| `APK_LAYERS` | `ui,visual,realtime,mobile` | слои для мобильной версии (`api` у сайта и приложения общий) |
| `APK_VISUAL_TOLERANCE` | `2` | разница яркости пикселя (из 255), которая считается сглаживанием |
| `APK_VISUAL_MAX_PIXELS` | `200` | сколько пикселей такого шума допускается на экране |
| `APK_PUSH_WAIT_S` | `20` | сколько ждать уведомления в канале приложения |
| `APK_INSECURE_UPSTREAM` | `0` | `1` — сервер с самоподписанным сертификатом (внешний режим) |

Папка проекта берётся из `PROJECT_DIR`: в Docker она подключается к
контейнеру тестов только для чтения.
