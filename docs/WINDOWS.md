# Запуск на Windows

## 1. Что нужно один раз

**Docker Desktop.** Это программа, которая запускает «контейнеры» —
изолированные мини-компьютеры внутри вашего. В них работают база данных,
сервер Kovapp и браузеры для тестов, поэтому на сам компьютер ничего,
кроме Docker, ставить не нужно.

1. Скачайте Docker Desktop с https://www.docker.com/products/docker-desktop/
   (кнопка «Download for Windows»).
2. При установке оставьте включённым пункт **Use WSL 2** — это встроенная в
   Windows подсистема Linux, через неё Docker работает быстрее всего.
3. Перезагрузите компьютер, если установщик попросит.
4. Запустите Docker Desktop и дождитесь зелёной надписи **Engine running**
   внизу слева. Регистрироваться в Docker не обязательно — окно входа можно
   закрыть.

Требования: Windows 10 22H2 или Windows 11, 8 ГБ оперативной памяти
(лучше 16), около 12 ГБ свободного места на диске для образов, интернет на
время первой сборки.

## 2. Подготовка папки

1. Распакуйте архив автотестов, например в `C:\kovcheg-autotest`.
   Путь лучше без русских букв и пробелов.
2. Положите проект Kovapp в папку `project` внутри неё так, чтобы
   получилось `C:\kovcheg-autotest\project\server\server.py`.
   Можно и не копировать: укажите путь к проекту в `.env`, например
   `PROJECT_DIR=C:/Projects/kovcheg` (косые черты — прямые).
3. Откройте `.env` в Блокноте и проверьте параметры (описание каждого —
   `docs/SETTINGS.md`). Для полного прогона менять ничего не нужно.

## 3. Запуск

Откройте папку в Проводнике, в адресной строке наберите `cmd` и нажмите
Enter — откроется командная строка уже в этой папке. Дальше:

```
run.cmd
```

Первый запуск собирает образы: скачивается около 3 ГБ, это занимает
10–30 минут. Следующие запуски начинаются сразу.

Полный прогон всех разделов в трёх браузерах идёт 2–4 часа: каждый раздел
проверяется для нескольких ролей, в двух темах, на двух размерах экрана и в
Chrome, Firefox и WebKit. С одним браузером (`BROWSERS=chrome` в `.env`) —
40–90 минут. Для быстрой проверки одного места запускайте отдельные разделы:

```
run.cmd full files
run.cmd full tasks task_view
```

Прогон против вашего сервера (он должен быть тестовым — тесты создают и
удаляют данные и рассылают уведомления):

1. Адрес сервера и вход администратора в `.env` уже заполнены из рабочего
   `.env` проекта (`EXTERNAL_BASE_URL`, `EXTERNAL_ADMIN_LOGIN`,
   `EXTERNAL_ADMIN_PASSWORD` — это аварийный вход `LOGIN_ADMIN` /
   `PASSWORD_ADMIN`). Если аварийный вход на сервере выключат
   (`ADMIN_FALLBACK_ENABLED=0`), впишите сюда обычную учётную запись
   директора или администратора.
2. Поставьте `EXTERNAL_CONFIRM_TEST_SERVER=1`, если этот сервер тестовый.
3. Запустите `run.cmd external`.

## Ускорение на мощном компьютере

Для i7 7-го поколения с 16 ГБ памяти:

1. Выделите Docker больше памяти. По умолчанию Docker Desktop берёт
   половину — 8 ГБ, для трёх исполнителей с тремя браузерами этого мало.
   Создайте в Блокноте файл `C:\Users\<ваше имя>\.wslconfig` с текстом:

   ```
   [wsl2]
   memory=12GB
   processors=8
   swap=4GB
   ```

   Затем в командной строке выполните `wsl --shutdown` и запустите Docker
   Desktop заново.
2. В `.env` поставьте `PARALLEL=3`.

Видеокарта тестам не помогает: браузеры в контейнере рисуют страницы
процессором. Если компьютер начнёт задыхаться (тесты падают по времени
ожидания), уменьшите `PARALLEL` до 2.

## 4. Где результат

`logs\<дата_время>_<режим>\summary.txt` — откройте его первым. В строке
«ВЫПОЛНЕНИЕ» процент успешных проверок, ниже — таблица по разделам и список
всех ошибок: что именно не так, у какой роли, в какой теме и на каком
экране, и снимок экрана к ошибке.

`full.log` рядом — подробности: по каждому тесту видно каждый шаг и каждый
запрос к серверу с ответом.

Хранятся последние 30 прогонов (параметр `KEEP_RUNS`).

## 5. Если что-то не так

| Сообщение | Что сделать |
|---|---|
| «Docker не найден» | установить Docker Desktop, перезапустить командную строку |
| «Docker Desktop не запущен» | запустить Docker Desktop и дождаться Engine running |
| «Сборка образов не удалась» | проверить интернет; повторить `run.cmd build` |
| «Сервер в Docker не запустился» | проверить `PROJECT_DIR` в `.env`; ниже в окне будут последние строки журнала сервера |
| «port is already allocated» | занят порт 18000 — поменять `FULL_PUBLISH_PORT` в `.env` |
| тесты раздела `visual` идут очень долго | уменьшить список ролей: `VISUAL_ROLES=director,worker_mont` |
| прогон нужно прервать | Ctrl+C, затем `run.cmd stop` |

Если версии библиотек на вашем сервере отличаются от сервера в Docker,
выполните на сервере `pip freeze > requirements-freeze.txt` и замените этим
файлом `docker\server-requirements.txt` (оставив в конце строки
`aiosmtpd` и `PyYAML`) — сервер в Docker станет точной копией боевого.
