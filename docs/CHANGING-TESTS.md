# Как перестраивать тесты

Тесты написаны на Python. Всё, что меняется чаще всего, вынесено из кода в
файлы настроек `config\*.yaml`: при изменении прав или раздела обычно
достаточно поправить одну строку, а не код.

## Где что лежит

| Путь | Что там |
|---|---|
| `config\permissions.yaml` | ожидаемые права: для каждого действия — список ролей, которым оно разрешено |
| `config\roles.yaml` | учётные записи тестовых ролей: статус, отдел, должность, логин |
| `config\ui.yaml` | разделы и их адреса, пункты меню, кто какие разделы видит, настройки проверки вёрстки и обхода кнопок |
| `config\ui_rights.yaml` | кнопки интерфейса и роли, которым они доступны |
| `config\sections.yaml` | список разделов тестирования, порядок их запуска, оценка длительности `weight` (по ней разделы делятся между исполнителями) и отметка `exclusive: true` для разделов, которые меняют общие настройки сервера и должны идти в одном исполнителе |
| `tests\<раздел>.py` | тесты раздела |
| `kovtest\` | сам механизм: запуск, журналы, браузеры, проверка вёрстки, работа с сервером |
| `kovtest_pc\` | ПК-версия (`run.cmd pc`): `run_pc.py` — все прогоны и отчёт, `unit.py` — проверки без окон, `harness.py` — запуск программы и шаги по таймеру, `plans\sections.py` и `plans\messenger.py` — что проверяется на экранах, `mock\` — тестовый сервер, `fixtures\` и `media\` — образцы видео, фото и файлов |

## ПК-версия: что поменять

- Новый раздел программы — строка `visit(...)` в `kovtest_pc\plans\sections.py`: адрес раздела,
  имя снимка и класс раздела; `need=` — для каких ролей, `bottom=True` — проверять нижнюю панель.
- Правило меню или склада изменилось — `expected_menu()` и `WAREHOUSE_DEPTS` в начале того же файла.
- Новый образец видео — файл в `kovtest_pc\fixtures`, его имя в `videos.json` и ожидание в таблице
  `EXPECT` файла `kovtest_pc\unit.py` (как сжать: на компьютере, как есть или сервером, стороны, кадры, звук).
- Новый ответ сервера, нужный программе, — в `kovtest_pc\mock\pc_mock.py` (форматы — как у `server_app`).

## Изменились права

Пример: складу разрешили добавлять позиции оборудования.

1. Откройте `config\permissions.yaml`, найдите действие `eq.edit`.
2. Добавьте роль в список `allow`: `allow: [management, buh, stock]`.
3. Запустите только проверку прав: `run.cmd full permissions`.

Роли в списке `allow` — это ключи из `config\roles.yaml` или группы из
начала `permissions.yaml` (`management`, `heads`, `mont_members` и т. д.).
Группу можно поменять один раз — изменение подействует на все действия,
где она указана.

Если действие новое, добавьте строку в `permissions.yaml` и функцию-попытку
в `tests\permissions.py` в словарь `ACTIONS`: функция получает роль, делает
запрос от её имени и возвращает ответ сервера. Тест «Матрица прав покрывает
все проверки» напомнит, если строка и функция разошлись.

Кнопки интерфейса проверяются так же, по `config\ui_rights.yaml`: у каждой
кнопки — адрес раздела, надпись и список `allow`. Для ролей из списка кнопка
должна быть доступна, для остальных — под замком или скрыта. Новая кнопка —
новый блок в этом файле, код менять не нужно.

## Появилась новая роль или отдел

Добавьте запись в `config\roles.yaml` (статус, отдел, должность, логин,
группы). В полном режиме учётная запись создастся при следующем запуске
сама, во внешнем — тоже, если `EXTERNAL_CREATE_ACCOUNTS=1`. Затем впишите
роль в нужные группы `permissions.yaml`.

## Изменился раздел интерфейса

Тесты ищут элементы по надписям на кнопках и по классам разметки.

| Что изменилось | Где поправить |
|---|---|
| адрес раздела или название в меню | `config\ui.yaml`, блоки `sections` и `menu` |
| кому виден раздел | `config\ui.yaml`, блок `access` |
| надпись на кнопке | в тесте раздела строка с `has_text="…"` или `visible_button("…")` |
| новый раздел | блоки `sections` и `menu` в `ui.yaml`, строка в `sections.yaml`, файл `tests\<раздел>.py` |
| кнопка, которую нельзя нажимать при обходе | `config\ui.yaml`, `crawler.skip_text` |
| элемент, который проверка вёрстки должна пропускать | `config\ui.yaml`, `audit.ignore` |

Проверка вёрстки (`visual`) и обход кнопок работают на любой разметке и
при изменении раздела обычно не требуют правок: они сами находят все
кнопки, поля и картинки на экране.

## Как выглядит тест

```python
from kovtest import case


@case("Кладовщик видит кнопку «Выдать»", layer="ui", order=5)
def stock_sees_issue(t):
    page = t.page("stock", "light", "desktop", path="#/equipment")
    t.check(page.visible_button("Выдать") is not None, "у кладовщика нет кнопки «Выдать»")
    page.audit("equipment_stock")
```

- `layer` — слой: `api` (запросы к серверу), `ui` (действия в браузере),
  `visual` (вёрстка), `realtime` (два пользователя сразу).
- `matrix={"theme": "themes", "device": "devices"}` — повторить тест во
  всех темах и на всех экранах из `.env`; `{"role": "roles:heads"}` — для
  всех ролей группы.
- `t.api("director")` — запросы к серверу от имени роли,
  `t.page(...)` — браузер с уже выполненным входом, `browser="B"` — второй,
  отдельный браузер.
- `t.check(условие, "что не так")` — проверка: при неудаче тест
  продолжается, ошибка попадает в итог; `t.require` — то же, но тест
  останавливается.
- `page.audit("имя")` — полная проверка вёрстки текущего экрана и снимок.

Новый тест достаточно дописать в файл раздела — отдельно регистрировать его
не нужно.

## Запуск части тестов

- Разделы: `run.cmd full tasks projects`.
- Слои: в `.env` `LAYERS=api` — только запросы к серверу, без браузеров
  (несколько минут вместо часа).
- Темы и экраны: `THEMES=light`, `DEVICES=desktop`.
- Роли для проверки вёрстки: `VISUAL_ROLES=director,worker_mont`.
