## Мобильная версия (`run.cmd mobile`)

Все разделы выше, кроме `push`, идут через интерфейс APK в Chromium (движок
Android WebView) на экранах `APK_DEVICES`. Дополнительно:

| Раздел | Проверки |
|---|---|
| `apk_shell` | надстройка на всех страницах; тексты «про браузер» заменены; цвет системных панелей из темы; «Назад»; «Загрузки» телефона; сеанс при входе и выходе; уведомления в открытом приложении; приглашение включить уведомления |
| `apk_push` | собственный канал уведомлений против серверного модуля `native_push`: доставка, чат (участнику, не автору и не постороннему), очередь без связи, секреты, отвязка при выходе, контрольное уведомление; сквозной сценарий в симуляторе |
| `apk_offline` | запуск без связи (интерфейс внутри APK), переподключение |
| `apk_fallbacks` | обработка файлов страницей по HTTPS и запасные пути телефона: отпечатки и видео по HTTP, фото HEIC, видео кодеком телефона |
| `apk_sim` | симулятор телефона: жизненный цикл приложения, «Назад», сеть, «Загрузки» |
| `apk_visual` | снимок каждого раздела в приложении против снимка сайта на том же экране — роли `VISUAL_ROLES`, обе темы, все экраны |

## ПК-версия (`run.cmd pc`)

| Часть | Проверки |
|---|---|
| `unit` | замены стилей мессенджера для старого движка Chromium 83 (у PySide6 — Chromium 134, страница без замен); функции мессенджера; уведомления (карточка, звук, системное при свёрнутом окне, когда не уведомлять); фото (EXIF, PNG, GIF, WebP, BMP, крупное → WebP 3200, прозрачность); отпечатки файлов как у сайта; gzip документов; видео — состав FFmpeg из комплекта (OpenH264, без частей под GPL), 12 образцов (HEVC, AV1, VP9, MJPEG, 60 к/с, поворот, две дорожки, фрагментированный MP4, 3GP, повреждённый) → H.264 High + AAC с нужными сторонами, частотой, звуком, длительностью и индексом в начале; правки видео; обложка; отправка группы файлов на тестовый сервер, ход отправки, видео кусками, gzip, отмена |

## Проверка вёрстки

На каждом проверенном экране и в каждом открытом окне:

- страница не шире экрана;
- кнопки, ссылки и поля не уходят за край экрана и за границы своего блока;
- элементы не наезжают друг на друга и не перекрыты другими элементами;
  закреплённые панели допускаются, если элемент можно прокрутить из-под них;
- кнопки не мельче 24 пикселей (на телефоне меньше 40 — предупреждение);
- картинки и миниатюры отрисовались, видео без ошибки воспроизведения;
- нет ошибок в консоли браузера и ответов сервера с ошибкой.

## Устройство: чат (`run.cmd device`, раздел `device_chat`) — с версии 2026-10-03.1

Проект v58–v59. Жесты настоящие (долгое нажатие и касания через Appium), состояние читается со страницы приложения.

| Проверка | Что подтверждает |
|---|---|
| Долгое нажатие на фото группы | выбран только этот файл, кружок у сообщения — «часть», всё сообщение без рамки, просмотр не открылся |
| Кружок у сообщения | выбирает всю группу сразу; касание по фото снимает один файл — снова «часть» |
| Пересылка одного файла группы | в другой чат приходит ровно выбранный файл, без подписи группы (по истории чата на сервере) |
| Удаление одного своего файла группы | на сервере и на экране в группе остаются остальные |
| Меню сообщения на телефоне | без пункта «Выбрать» — выбор долгим нажатием |
| Шапка мессенджера | в открытом чате нет верхней строки приложения, в списке чатов — есть |
| Просмотр фото | не сдвигается у крайнего снимка, щипок приближает, свайп вниз закрывает |

## Проекты: завершение, архив, только чтение, доступ к этапам (`projects_archive`, сервер)

| Проверка | Что должно быть |
|---|---|
| Завершить при незавершённой задаче | 400; `can_complete` у создателя, `tasks_unfinished` ≥ 1 |
| Завершить сотрудником (не создатель, не директор, не администратор) | 403 |
| Завершение директором | проект в «Архивных» и не в «Активных»; сохранены кто (`archived_by`) и когда (`archived_at`); `can_edit` и `can_upload` выключены |
| Только чтение | 409: правка проекта, файл в раздел, правка склада, правка, удаление и возврат в работу задачи, отправка файла в задачу, новая задача в проекте; права склада выключены |
| Вернуть в работу | сотрудником — 403; директором — проект снова в «Активных», правится; запись, кто завершал, сохраняется |
| Задачи проекта | видны все; недоступная — `can_open=false` и не открывается (403); своя — `can_open=true` |
| Медиаконтент и файлы этапа | монтажник не видит в медиаконтенте файл этапа отдела ТО и не открывает его по ссылке (403); свой — видит (200); руководство — все |
| Срок при создании | проект и задача со сроком вчера — 400 |

## Добавлено в beta3-v1

### compression — качество сжатия (ручной раздел, `run.cmd compression`)
- одни и те же исходники (фото 4032×3024, PNG, видео 12 с и 64 с в 1080p, документ CSV) сжимаются
  в браузерах (кодом сайта), на сервере, на телефоне (видео — родным кодеком через галерею приложения)
  и в ПК-версии (код программы, FFmpeg из комплекта с OpenH264; добавлено в beta3-v9);
- точно совпадают: стороны, частота кадров, звуковые дорожки; длительность — до 0,1 с;
  документ после распаковки — байт в байт;
- в допуске: сходство с оригиналом (SSIM) и размер результата между местами;
- отчёт `compression-report.html`; результаты мест хранятся в `logs\compression-results`.

### load — нагрузка по ступеням (ручной раздел, `run.cmd load`)
- пределы сервера посчитаны по урезанной машине и применены;
- ступени от `LOAD_USERS` до `LOAD_USERS_MIN`: переписка, списки и карточки, файлы, «телефоны»
  с каналом уведомлений приложения, живой браузер;
- на каждой ступени: время подключения, доставки сообщений и уведомлений, открытия списков и
  страниц, отправки файлов по видам, процессор, память, задержка обработки, база;
- ничего не теряется и нет ошибок на каждой ступени; пороги — на самой большой;
- отчёт `load-report.html` (таблица и графики), `load-steps.json`, медленные запросы базы.

### Объединённые проверки
- `tasks`: список задач не перерисовывается, пока в нём ничего не изменилось;
- `messenger`: счётчик новых сообщений на кнопке «вниз»; большие и повторные файлы из задачи и
  напрямую; пересылка части группы (`file_ids`);
- `network`: обрыв сети при отправке файла в чат (компьютер);
- `realtime`: новые записи проверяются по ответам сервера (учитывает лёгкий список задач `/tasks/light`).
