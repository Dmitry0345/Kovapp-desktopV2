# Как устроена мобильная версия Kovapp

## Главная идея

Приложение — это окно WebView, в котором работает **та же веб-версия**
(`web_app`). Отличие от браузера одно: файлы интерфейса берутся не из сети,
а из самого APK, но под адресом вашего сервера (`https://сервер/app/…`).
Поэтому:

- интерфейс открывается без интернета, а все запросы к API идут на тот же
  адрес, что и у сайта (без CORS и отдельных настроек сервера);
- внешний вид и поведение совпадают с сайтом — это буквально тот же код;
- страница «защищённая» (HTTPS), поэтому в приложении работают те же
  механизмы, что в Chrome: сжатие видео через WebCodecs, отпечатки файлов
  через `crypto.subtle`, сжатие фото на canvas.

```
┌──────────────── APK ────────────────┐          ┌──── сервер ────┐
│ MainActivity                        │  HTTPS   │ FastAPI        │
│  └ WebView ── /app/* из APK ───────────────────▶ API, /ws/chat │
│      │  (AssetServer + надстройка)  │          │                │
│      └─ мост kovNativePort ──┐      │  wss     │ native_push    │
│ Службы: уведомления, файлы,  ◀──────────────────  /ws/native-push│
│ сжатие фото/видео, загрузки         │          │ → FCM (Google) │
└─────────────────────────────────────┘          └────────────────┘
```

## Надстройка над веб-версией

Файлы `web_app` не меняются. При выдаче страницы из APK в неё добавляются
три скрипта (`overlay/inject.json`):

| Скрипт | Когда | Что делает |
|---|---|---|
| `native/kovapp-state.js` | в начале | состояние телефона: разрешения, уведомления |
| `native/kovapp-bridge.js` | в начале | мост к приложению; системные уведомления вместо браузерных |
| `native/kovapp-app.js` | перед `app.js` | подключает модули веб-версии к возможностям телефона |

И девять точечных правок текстов, неверных в приложении (`overlay/web-patches.json`):
например, «значок замка слева от адреса» — адресной строки в приложении нет.
Каждая правка обязана найтись в файле ровно один раз, иначе пропускается и
пишет предупреждение: изменение веб-версии не сломает приложение молча.

## Что делает телефон, а что — страница

Правило: **где страница справляется сама — работает код веб-версии**
(полное совпадение с сайтом). Телефон подключается только как запасной путь:

| Задача | Обычно (HTTPS) | Запасной путь телефона |
|---|---|---|
| Сжатие видео | WebCodecs страницы | аппаратный кодек (MediaCodec) — когда нет WebCodecs, декодера или страница слишком медленная |
| Сжатие фото | canvas страницы | когда браузерный движок не распаковал фото (HEIC) |
| Отпечаток файла | `crypto.subtle` страницы | по HTTP, где `crypto.subtle` нет |
| Уведомления | — | всегда телефон: в WebView нет Web Push |
| Скачивание | — | всегда телефон: в «Загрузки» |

Запасные пути дают **тот же результат**, что и код страницы: Java-код
перенесён с `web_app/js/media/*` и сверяется с ним тестами побайтно (разбор
и сборка MP4, расчёты плана сжатия, отпечатки, размеры картинок).

## Уведомления

| | Через Google (FCM) | Собственный канал |
|---|---|---|
| Где | телефоны с сервисами Google, если настроен Firebase | телефоны без Google (Huawei, Honor) или без настроенного Firebase — в том же APK |
| Как | сервер шлёт шифртекст в Google, телефон расшифровывает | служба держит WebSocket с сервером |
| Если телефон офлайн | хранит Google | хранит очередь сервера |

Когда приложение открыто, уведомление показывает сама страница — как
service worker сайта. Когда свёрнуто или закрыто — система Android, с теми
же заголовком, текстом и меткой, что у сайта.

## Файлы

| Путь | Назначение |
|---|---|
| `app/src/main/java/ru/kovcheg/kovapp/MainActivity.java` | окно, WebView, «Назад», дочерние окна документов |
| `…/web/AssetServer.java`, `Overlay.java`, `WebRules.java` | выдача интерфейса из APK, надстройка, заголовки безопасности |
| `…/web/Bridge.java`, `…/NativeCommands.java` | мост и команды страницы |
| `…/push/*` | уведомления: FCM, собственный канал, досылка, хранение секретов |
| `…/media/*` | запасное сжатие видео и фото, отпечатки |
| `…/files/*` | выбор файлов и камера, «Загрузки» |
| `server/server_app/native_push.py`, `routers/native_push.py` | серверный модуль уведомлений |
