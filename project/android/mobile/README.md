# Kovapp для Android

Приложение для телефона на основе веб-версии «Ковчега». Внешний вид и
функции — те же, что у сайта: приложение показывает те же файлы `web_app`,
только взятые из самого APK. Поэтому интерфейс открывается без интернета,
а данные идут с того же сервера. Сверх сайта приложение умеет:

- **уведомления при закрытом приложении** — через Google (FCM) или по
  собственному каналу для Huawei, Honor и любых телефонов без Google;
- **сжатие фото и видео на телефоне**, когда браузерный движок не справился
  сам (например, фото HEIC или работа по HTTP);
- **скачивание в «Загрузки»**, камеру в окне выбора файлов, кнопку «Назад»,
  которая сначала закрывает окна и меню;
- **вопрос перед уходом со страницы** во время отправки файла (нажатие на
  уведомление, жест «Назад») вместо молчаливой отмены отправки.

Файлы веб-версии не меняются: всё, что нужно приложению, добавляется при
сборке APK (папка `overlay/`). Сайт в браузере работает как раньше.

## Что внутри

| Папка | Что это |
|---|---|
| `app/` | исходники приложения (Java) и ресурсы |
| `overlay/` | надстройка: скрипты приложения и правки текстов «про браузер» |

| `tools/build/Dockerfile` | сборка APK в Docker без Android Studio |
| `tests/` | тестовый сервер, тесты и отчёты |

## 1. Настройки сборки

Скопируйте `kovapp.properties.example` в `kovapp.properties` и впишите
адрес сервера:

```properties
serverOrigin=https://kovcheg.example.ru
debugServerOrigin=http://localhost:8000
```

- `serverOrigin` — адрес для рабочей сборки, **только https**. Интерфейс
  откроется по `<адрес>/app/`, как и сайт. Если указать `http://`, сборка
  остановится с объяснением: так приложение защищено от подмены сервера.
- `debugServerOrigin` — адрес для отладочной сборки. Отладочная сборка
  может ходить по http, но только на `localhost`, `127.0.0.1` и `10.0.2.2`
  (это ваш ПК, если смотреть из эмулятора).

Файл `kovapp.properties` не кладите в git и в архивы: там адреса и ключи.

### Если у сервера свой сертификат

Сертификат от Let's Encrypt или другого известного центра подходит сразу.
Если сертификат самоподписанный (сделан на самом сервере), положите его
файл (`.pem` или `.crt`, только открытая часть!) рядом и укажите:

```properties
serverCertificate=certs/server.pem
```

Приложение будет доверять этому сертификату **только для вашего адреса** —
на другие сайты это не распространяется.

## 2. Ключ подписи

Android устанавливает только подписанные приложения, а обновление ставится
поверх, только если подписано тем же ключом. Ключ создаётся один раз и
хранится бережно: потеряете — обновить приложение у людей не получится,
придётся удалять и ставить заново.

```bash
keytool -genkeypair -v -keystore kovapp-release.jks -alias kovapp \
        -keyalg RSA -keysize 4096 -validity 10000
```

`keytool` входит в JDK. Затем создайте `keystore.properties` рядом с
`kovapp.properties`:

```properties
storeFile=kovapp-release.jks
storePassword=пароль_хранилища
keyAlias=kovapp
keyPassword=пароль_ключа
```

Без этого файла рабочая сборка получится неподписанной, а отладочная
(`debug`) подписывается учебным ключом Android Studio — её можно ставить
для проверки.

## 3. Сборка

APK один на все телефоны. Способ доставки уведомлений выбирает сам телефон
при включении уведомлений:

| Телефон | Уведомления |
|---|---|
| с сервисами Google (Pixel, Samsung, Xiaomi…) | через Google (FCM) — если настроен Firebase (раздел 5) |
| без сервисов Google (Huawei, Honor…) или Firebase не настроен | собственный канал: постоянное соединение с сервером |

Если Google на телефоне есть, но токен получить не удалось, приложение тоже
переходит на собственный канал. Без Firebase всё работает, просто везде через
собственный канал.

### Вариант А. Android Studio (проще всего)

1. Установите Android Studio (developer.android.com/studio). Если при запуске
   появляется «SDK Problem», а в настройках пустое «Android SDK Location» —
   не установлен Android SDK: Settings → Languages & Frameworks → Android SDK →
   ссылка **Edit** → установите SDK в `C:\Android\Sdk` (путь латиницей) и
   добавьте на вкладке SDK Platforms «Android 16 (API 36)».
2. «Open» → папка `mobile`. Студия сама скачает Gradle и нужные части
   Android SDK. Если предложит обновить Android Gradle Plugin — соглашайтесь.
3. Меню «Build» → «Generate Signed App Bundle or APK…» → APK → выберите
   ключ из раздела 2 → вариант `release`.
4. Готовый файл: `mobile/app/release/app-release.apk`.

### Вариант Б. Docker (без установки Android Studio)

Из папки `kovcheg`:

```bash
docker build -t kovapp-build mobile/tools/build
docker run --rm -v "$PWD:/work" kovapp-build
```

В Windows (PowerShell) вместо `$PWD` — `${PWD}`, в cmd — `%cd%`. Готовые
APK: `mobile/app/build/outputs/apk/`. Первый запуск скачивает около 1 ГБ.

### Вариант В. Командная строка

Нужны JDK 17+, Android SDK (переменная `ANDROID_HOME`) и Gradle 8.14+:
`build.sh` (Linux, macOS) или `build.bat` (Windows).

## 4. Обновление сервера

Приложению нужен модуль уведомлений на сервере. Всё остальное API общее с
сайтом.

1. Скопируйте папку `server` поверх старой (как при обычном обновлении).
2. Перезапустите сервер. Таблица `native_push_devices` создаётся сама; для
   ручного обновления базы есть `sql/kovcheg-native-push.sql`.
3. В журнале при старте появится строка «Уведомления приложения Kovapp:
   включены, через Google (FCM): нет — …». Для Huawei/Honor этого достаточно.

Настройки в `.env` (все необязательные):

| Переменная | Значение |
|---|---|
| `NATIVE_PUSH_ENABLED` | `0` — выключить уведомления приложения (по умолчанию включены) |
| `FCM_SERVICE_ACCOUNT_FILE` | путь к ключу сервисного аккаунта Firebase (раздел 5) |
| `NATIVE_PUSH_PING_SECONDS` | как часто проверять связь с телефоном, по умолчанию 240 |
| `NATIVE_PUSH_QUEUE` | сколько уведомлений хранить на телефон, пока он офлайн, по умолчанию 100 |

**nginx.** Собственный канал идёт через `/ws/native-push`. Блок
`location /ws/` из основной инструкции уже подходит: там включён переход на
WebSocket и таймаут `proxy_read_timeout 3600s`. Ничего добавлять не нужно.

Как это работает, простыми словами: телефон без Google держит с сервером
одно тихое соединение. Раз в 4 минуты сервер «пингует» телефон, чтобы
соединение не оборвали роутеры. Уведомление приходит по этому соединению
мгновенно; если телефон был без связи, сервер хранит уведомления в очереди
и отдаёт их при подключении.

## 5. Уведомления через Google (необязательно)

1. console.firebase.google.com → создать проект → добавить Android-приложение
   с именем пакета `ru.kovcheg.kovapp`.
2. «Настройки проекта» → «Общие» → ваше приложение: перепишите в
   `kovapp.properties` значения `fcmProjectId`, `fcmAppId` (mobilesdk_app_id),
   `fcmApiKey` (current_key), `fcmSenderId` (project_number). Файл
   `google-services.json` класть в проект **не нужно**.
3. «Настройки проекта» → «Сервисные аккаунты» → «Создать закрытый ключ».
   Скачанный JSON положите на сервер (например, `/opt/kovcheg/fcm-key.json`),
   закройте от чужих глаз (`chmod 600 fcm-key.json`) и укажите путь в `.env`:
   `FCM_SERVICE_ACCOUNT_FILE=/opt/kovcheg/fcm-key.json`.

Текст уведомления шифруется ключом каждого телефона — Google видит только
зашифрованные байты.

## 6. Установка и первый запуск

1. Передайте APK на телефон и откройте его. Android попросит разрешить
   установку из этого источника — разрешите.
2. Войдите. Приложение само предложит включить уведомления, как сайт.
3. «Настройки» → карточка «Это устройство» — там видно, каким путём идут
   уведомления, и есть кнопка «Проверить» (контрольное уведомление с
   подтверждением доставки).

**Huawei и Honor.** Эти прошивки «усыпляют» приложения в фоне. Приложение
само попросит разрешение работать без ограничений батареи, но у Huawei и
Honor нужен ещё один шаг: «Настройки» → «Приложения» → «Запуск приложений» →
Kovapp → «Управлять вручную» → включите все три переключателя. Подсказка
есть и в самом приложении («Настройки» → «Это устройство»).

Значок «Kovapp на связи» в шторке появляется, когда уведомления идут собственным
каналом. Приложение само скрыть его не может (так устроен Android). Как убрать,
не теряя уведомлений: «Настройки» → «Это устройство» → «Убрать значок» → на
открывшемся экране выключите переключатель в самом верху. На Android 13+ его
можно и смахнуть. При доставке через Google (раздел 5) значка нет.

**Старые телефоны.** Нужен Android 7.0 и новее и «Android System WebView»
версии 90+ (для полного совпадения внешнего вида — 111+). Если движок
старый, приложение покажет экран с кнопкой обновления.

## 7. Проверка на ПК без телефона

### Симулятор телефона (основной способ)

Двойной щелчок по `mobile/simulator.bat` (Windows) или команда

```bash
python mobile/tools/simulator.py
```

откроет браузер с «телефоном». Нужен только Python 3.8+, ничего
устанавливать не надо. Внутри — то же приложение, что в APK (та же
надстройка над веб-версией), а вокруг — всё, чем телефон отличается от
браузера:

![Симулятор телефона](../docs/images/simulator.png)

| Где | Что можно проверить |
|---|---|
| Кнопки ◁ ○ ▢ под экраном | «Назад» (закрывает окна и меню, как в APK), «Домой» (свернуть), «Недавние» (вернуться или **закрыть приложение**) |
| «Уведомления» слева | разрешение телефона, работа без ограничений батареи, состояние канала уведомлений, проверочное уведомление |
| «Шторка уведомлений» справа | системные уведомления, когда приложение свёрнуто или закрыто; нажатие открывает нужный раздел (при закрытом приложении — холодный запуск сразу в него) |
| «Сеть» слева | «Нет» — связь с сервером обрывается по-настоящему, интерфейс остаётся; «Медленная» — задержка 1,5 с на каждый запрос |
| «Загрузки» справа | файлы, которые приложение сохранило бы в «Загрузки» телефона |
| «Телефон» слева | размер экрана (от 320×640 до планшета), поворот, масштаб |
| «Журнал моста» | каждая команда приложения к «телефону» и ответ — удобно при отладке |

Тестовый сервер симулятора «живой»: в чатах есть история, а сообщения,
фото и файлы (в чатах и задачах) сохраняются, пока он запущен. Ссылка
«Открыть сайт под другим сотрудником» в симуляторе открывает сайт на том же
сервере — войдите там другой ролью и переписывайтесь с «телефоном».

Уведомления в симуляторе идут **по настоящему каналу приложения** к
серверу (`/ws/native-push`) — тем же путём, что на Huawei и Honor. Поэтому
можно проверить главный сценарий: войти, включить уведомления, закрыть
приложение («Недавние» → «Смахнуть»), отправить сообщение — оно придёт в
шторку, а нажатие откроет нужный чат.

**С тестовым сервером** (по умолчанию) вход: логин — роль (`director`,
`admin`, `head`, `worker`, `montage`, `to`, `contract`, `stock`,
`accountant`, …), пароль `test`. Изменения не сохраняются. Кнопка
«Сообщение от коллеги» присылает уведомление чата.

**С рабочим сервером** — настоящие данные и настоящие уведомления:

```bash
python mobile/tools/simulator.py --server https://kovcheg.example.ru
```

Откройте рядом сайт под другим сотрудником и напишите в чат —
уведомление придёт в симулятор. Серверу нужен модуль уведомлений
(раздел 4).

Чем симулятор не является: это не Android, а браузер Chrome, на движке
которого построен Android System WebView. Внешний вид и логика совпадают
(это проверяют автоматические тесты), но аппаратное сжатие видео, камера,
энергосбережение прошивок и настоящая доставка через Google проверяются
только на телефоне — список в `docs/mobile-test-report.md`.

### Интерфейс приложения в обычной вкладке

```bash
python mobile/tests/mock/mock_server.py            # тестовый сервер на :8000
python mobile/tools/devserver.py --bridge          # приложение на :8790
```

`http://localhost:8790/app/` — интерфейс с надстройкой без «телефона»
вокруг, удобно для инструментов разработчика Chrome (F12).

**Проверка запасных путей для HTTP.** `localhost` браузер считает
защищённым адресом, как HTTPS. Чтобы увидеть поведение по чистому HTTP,
откройте тот же адрес по имени компьютера в сети (например,
`http://192.168.1.10:8790/app/`, запустив devserver с `--host 0.0.0.0`).

### Отладочный APK в эмуляторе Android Studio

Нужны установленный Android SDK и включённая в Windows «Платформа
низкоуровневой оболочки Windows» (ускорение эмулятора). Эмулятор создаётся в
Device Manager: в открытом проекте — значок телефона справа или View → Tool
Windows → Device Manager; на экране приветствия — More Actions → Virtual
Device Manager. Образ системы — Android 16 (API 36), x86_64.

1. `debugServerOrigin=http://localhost:8000` в `kovapp.properties` (или
   `http://10.0.2.2:8000` — тогда `adb reverse` не нужен, но адрес
   незащищённый и проверяются запасные пути телефона).
2. Запустите тестовый сервер (`simulator.bat` держит его на порту 8000), затем в терминале:
   `adb reverse tcp:8000 tcp:8000` — эмулятор увидит ваш ПК как свой localhost.
3. Запустите вариант `debug` из Android Studio (он выбран по умолчанию).

Правка интерфейса без пересборки APK: `devAssetsUrl=http://localhost:8790`,
`python mobile/tools/devserver.py --assets`, `adb reverse tcp:8790 tcp:8790` —
отладочный APK берёт файлы интерфейса с ПК при каждом открытии страницы.

### Автоматические тесты

Всё сразу, со сводным отчётом в `docs/mobile-test-report.md`:

```bash
python mobile/tools/run_all_checks.py          # без UI-тестов, пара минут
python mobile/tools/run_all_checks.py --ui     # вместе с UI-тестами, около часа
```

По отдельности:

```bash
python mobile/tools/offline-check/run_jvm_tests.py   # код приложения против веб-версии и сервера
python mobile/tools/offline-check/overlay_parity.py  # надстройка APK = надстройка на ПК
python mobile/tools/security_check.py                # правила безопасности
python mobile/tests/ui/run_ui_tests.py               # внешний вид, права по ролям, надстройка
python -m server.tests.native_push_tests             # серверный модуль уведомлений (из папки kovcheg)
python -m server.tests.fixes_2026_09_25_tests        # исправления 25.09 (из папки kovcheg)
```

Полная проверка мобильной версии с настоящим сервером в Docker — в системе
автотестов `kovcheg-autotest`: команда `run.cmd mobile` (все разделы сайта
через интерфейс APK плюс разделы `apk_*`, см. её `docs/MOBILE.md`).

Для UI-тестов нужен Python-пакет Playwright:
`pip install playwright pillow` и `python -m playwright install chromium`.
Отчёт — `mobile/tests/ui/report/report.md`, снимки — рядом. В Android
Studio те же Java-тесты запускаются задачей `testDebugUnitTest`.

## 8. Если что-то не так

| Признак | Что проверить |
|---|---|
| Сборка: «Нет адреса сервера» | есть ли `kovapp.properties` с `serverOrigin` |
| Сборка: «Рабочая сборка работает только по https» | адрес должен начинаться с `https://` |
| Приложение: «Нет связи с сервером» при рабочем сайте | сертификат: самоподписанный нужно указать в `serverCertificate` |
| Уведомления не приходят при закрытом приложении | «Настройки» → «Это устройство» → «Проверить»; на Huawei/Honor — раздел 6 |
| «Для уведомлений при закрытом приложении обновите сервер» | на сервере нет модуля `native_push` (раздел 4) |
| Экран «Обновите WebView» | обновите «Android System WebView» (или «Huawei WebView») в магазине |
