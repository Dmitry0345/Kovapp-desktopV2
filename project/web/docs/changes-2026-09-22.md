# Изменения от 22.09.2026

## Превью фото и видео, скачивание файлов

| Что было | Что стало | Где |
|---|---|---|
| Окно просмотра запрашивало фото по адресу `/stream/`, который для картинок всегда отвечает 400; фото открывалось только через запасной переход на скачивание | Фото открывается адресом просмотра (`/view`), видео — `/stream/`, скачивание — последний запасной вариант | `web_app/js/core/files.js` |
| Если миниатюра не грузилась, плитка тоже лезла в `/stream/` | Сначала повтор со свежим файловым токеном, потом адрес просмотра, потом значок | `web_app/js/core/files.js` |
| Скачивание по номеру файла читало файл целиком в память и распаковывало его, а затем сервер ещё раз сжимал ответ gzip уровня 9 — большое скачивание подвешивало сервер для всех | Файлы отдаются потоком с поддержкой Range, файловые адреса выведены из-под gzip | `routers/files.py`, `routers/projects.py`, `routers/chat.py`, `core.py` |
| Тип `.webp` был неизвестен Python без системного файла типов: `/view` для фото отвечал 415, скачивание шло как «неизвестный файл» | Тип зарегистрирован | `config.py` |
| Файловый токен (20 минут) и токен сессии считали срок по местному времени сервера, а проверялись по всемирному: по Москве файловый токен жил 3 ч 20 мин, при поясе западнее UTC — рождался просроченным | Срок считается по UTC | `core.py`, `routers/auth.py` |
| После сна компьютера или долгой фоновой вкладки токен протухал, миниатюры ломались | Токен обновляется при возвращении на вкладку, при фокусе и появлении сети; при ошибке загрузки — повтор со свежим токеном | `web_app/js/kov-api.js`, `files.js`, `downloads.js` |
| Ошибка скачивания показывала только код ответа | Показывается объяснение сервера; при 401 — повтор со свежим токеном | `web_app/js/core/downloads.js` |
| Мессенджер клал в ссылки на файлы основной токен сессии | Кладёт короткий файловый токен и обновляет его в открытом чате | `web_app/js/views/messenger.js` |

## Доступ к файлам (подробно — `file-access-plan.md`)

- Новый модуль `server/server_app/file_access.py`: владелец файла по пути
  (чат, проект, оборудование, задача), проверка права, кэши, режим
  `FILE_ACCESS_STRICT` (0 — только запись «отказ бы был», 1 — отказ 403).
- Проверка включена на `/file_storage/…`, `/file_storage/messenger/…`,
  `/chat/download/<путь>`, `/file_preview/…`, `/sheet_preview/…` и при
  скачивании вложения чата по номеру сообщения.
- Участники и ответственные этапа теперь открывают файлы задачи: раньше они
  видели плитки в разделе «Фото» проекта, но получали 403.
- Индексы по путям файлов (создаются при старте сервера).
- Диагностика: `GET /health/file-access`.
- Скрипт `server/find_orphan_files.py` — поиск файлов без записи в базе.

## Права: сервер и интерфейс приведены к одним правилам

| Правило | Что было не так |
|---|---|
| Руководитель отдела заводит задачу с одним этапом своего отдела, другие отделы подключаются только продлением | Правило было записано в `rights.js`, но не применялось ни в форме, ни на сервере. Теперь форма даёт руководителю один этап своего отдела, сервер проверяет создание, создание из шаблона и правку этапов |
| Править, удалять и возвращать из архива задачу может руководство или руководитель отдела, к которому относятся все её этапы | Кнопки показывались любым руководителям, сервер отвечал 403. Теперь у чужой задачи кнопка с замком и причиной |
| Продлить задачу может руководство, руководитель отдела и ответственный за последний этап | Руководителям отделов кнопка была заперта, хотя сервер разрешал |
| Запросить завершение задачи может руководство, руководитель отдела задачи и ответственный за последний этап (в договорном отделе — любой названный сотрудник) | Сервер отказывал ответственному за этап; кнопка при этом была открыта |
| Шаблоны задач ведут директор и администратор | Кнопки создания, правки и удаления шаблонов были открыты руководителям отделов, сервер отвечал 403 |
| Состав этапа меняет ответственный за этап (их может быть несколько — например, руководитель и заместитель) | Через `PUT` состав мог переписать любой сотрудник отдела. `POST` не вносил новых участников в состав задачи, падал на повторе и ошибочно требовал «назначить другого ответственного» |
| Состав этапа, выбранный при продлении, не меняется сам | Окно задачи при каждом открытии этапа переписывало состав на весь отдел (оставшееся от старого правила), всем приходило «Вас добавили в задачу»; форма задачи делала то же при каждом сохранении |
| При смене отдела этапа ответственными становятся руководители нового отдела | Названные ответственные прежнего отдела оставались |
| Свои телефон и почту меняет сам сотрудник | Сервер отвечал 403 всем, кроме руководства |
| Участники задачи уведомляют друг друга о своих действиях в задаче | Сотрудник, завершивший этап, получал ошибку «Уведомление не отправлено» |
| Файлы задачи добавляет руководство, файлы этапа — его отдел; в архиве и в завершённом этапе файлы не меняются | Сервер пускал любого участника задачи и позволял менять файлы в архиве |
| Удалить файл задачи может руководство, руководитель отдела задачи и тот, кто его прикрепил | Интерфейс показывал удаление только руководству |
| Проекты создают руководство, руководители отделов и договорной отдел | Интерфейс разрешал договорному отделу, сервер отвечал 403 |
| Служебные адреса `/health/*` — директору и администратору по полю статуса | Проверялось слово в названии должности |
| Журнал задачи — только её составу | Читался без проверки прав |

## Ошибки

- Удаление проекта с задачами падало с ошибкой 500 (не хватало импортов в
  `routers/projects.py`).
- `GET /organizations/search` перехватывался маршрутом `/organizations/{id}`
  и отвечал 422.
- 23 обработчика в 8 модулях превращали ответы 400, 403, 404 и 409 в 500
  с текстом вида «Ошибка при …: 403: …». Теперь коды доходят как есть.
- Чат: загрузить файл в чужой чат и заменить аватар любой группы мог любой
  сотрудник; реакции, сведения о группе и состав альбома были доступны не
  участникам. Теперь нужно членство в чате, а аватар меняет администратор
  группы.

## Найдено автотестами и исправлено

- Вложение сообщения, отправленного через сокет, должно лежать в папке своего
  чата. Раньше в сообщение можно было подставить путь к файлу чужого чата и
  получить к нему доступ через пересылку по пути (`routers/chat_ws.py`).
- На телефоне переключатели-вкладки не помещались в строку: в «Оборудовании»
  обрезалась кнопка «Ждут ответа», в «Файлах CSV» — «Организации». Теперь
  они переносятся на вторую строку (`css/app.css`).
- В «Оборудовании» поля «Изменить» (название и количество) были высотой
  20 пикселей — по ним трудно попасть. Область нажатия увеличена до 28
  пикселей без изменения вида (`css/app.css`).
- Кнопка действий с сообщением в чате была 22×22 пикселя — увеличена до 28
  в веб-версии (`css/app.css`).
- В «Проектах» точки переключения страниц столбцов («Показать руководителей
  1–4», «5–8») были 7–10 пикселей. Точка выглядит как прежде, а нажимать
  теперь можно по кругу 28 пикселей (`css/app.css`).
- `chat/chat.js`: снятие отметки «новое сообщение» искало сообщение по
  номеру позиции в списке; если список за 0,4 с менялся, в консоль падала
  ошибка «Cannot set properties of undefined». Теперь сообщение ищется по
  его номеру.
