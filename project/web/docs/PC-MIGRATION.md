# Перенос изменений beta 3 в ПК-версию (настольное приложение)

ПК-версия, присланная 05.10.2026 (`app (2).zip` и `server (8).zip`, файлы от 27.08.2026),
старше исходной версии веб-разработки (13–22.09). Её сервер заменяется сервером beta 3,
поэтому приложение нужно довести до нынешних правил и форматов. Ниже — что именно
изменилось для него на сервере и что сделать в приложении, по шагам.

Опорная реализация каждой функции — веб-версия `web_app` (тот же сервер, те же правила):
при переносе экрана открывайте соответствующий файл `web_app/js/views/*.js`.

## 2. Подключение к серверу

1. **Один адрес и порт — через nginx.** На рабочем сервере (`KOVAPP_ROLE=split`) сервер
   работает несколькими процессами, и только nginx знает, какой запрос куда отправить.
   Приложение должно ходить на адрес nginx (как сайт), а не на внутренние порты 54545–54548.
2. **HTTPS и WSS.** Рабочая установка — по HTTPS. Адрес сервера в приложении — `https://…`,
   веб-сокет чата — `wss://…/ws/chat`. Запасной путь по HTTP оставить для локальной проверки.
3. **Срок токена — по всемирному времени (UTC).** Если приложение само проверяет срок
   токена, считать его в UTC: раньше сервер выдавал срок по местному времени.

## 3. Правила, которые теперь проверяет сервер

Сервер отклоняет действие ответом 403, 409 или 400 с понятным текстом в поле `detail`.
Приложению нужно показывать этот текст человеку, а кнопки недоступных действий
блокировать заранее (как в `web_app/js/core/rights.js`). Полная таблица прав — `docs/permissions.md`.

| Правило | Ответ сервера | Что сделать в приложении |
|---|---|---|
| Руководитель отдела создаёт задачу только с одним этапом своего отдела; другие отделы — продлением | 403 | в форме задачи — один этап своего отдела |
| Править, удалять, возвращать из архива — руководство или руководитель отдела всех этапов | 403 | замок на кнопках чужой задачи |
| Продлить — руководство, руководитель отдела, ответственный за последний этап | 403 | |
| Состав этапа меняет ответственный за этап (их может быть несколько) | 403 | |
| Файлы задачи добавляет любой, кому открыта задача (с версии 12; раньше — руководство), файлы этапа — его отдел; в архиве и в завершённом этапе файлы не меняются | 403 | зона файлов задачи открыта всем участникам |
| Файлы этапа видят только руководство и сотрудники отдела этапа (и по прямой ссылке) | 403 | плитки чужих этапов не показывать |
| Срок при создании задачи и проекта — не раньше сегодняшнего дня | 400 | ограничить календарь |
| Завершённый проект — только чтение: любые изменения его задач, этапов, файлов, склада | 409 | кнопки скрыть, пояснение «Проект завершён» |
| Задачу нельзя вернуть в работу, пока её проект завершён | 409 | |
| Шаблоны ведут директор и администратор | 403 | |
| Служебные `/health/*` — директору и администратору | 403 | |

## 4. Файлы: форматы и доступ

1. **Доступ к файлу = доступ к записи, которой он принадлежит** (задача, этап, проект, чат).
   При `FILE_ACCESS_STRICT=1` чужой файл — 403. Ссылки на файлы приложение отправляет с
   заголовком `Authorization: Bearer …` — так и оставить.
2. **Фото хранятся в WebP.** PyQt5 показывает WebP через модуль форматов изображений
   (`imageformats/qwebp`). Проверьте на рабочих компьютерах: открывается ли фото,
   загруженное с телефона после 24.09. Если нет — поставить пакет `PyQt5` новее или
   добавить модуль `qwebp`.
3. **Видео — MP4 (H.264 + AAC).** До Full HD 1920 у роликов до минуты и HD 1280 у длинных.
4. **Документы на сервере хранятся сжатыми (`.gz`).** Приложению сервер отдаёт их
   распакованными, как раньше (ответ без `ce=1`). Ничего менять не нужно.
5. **Миниатюры** — рядом с файлом `<файл>.thumb.jpg` (фото и видео, в том числе в чате);
   у старых видео обложка создаётся при первом запросе.
6. **Отправка больших файлов.** Прежняя отправка одним запросом (`/upload`, `/chat/upload`)
   работает. Сайт и телефон шлют файлы больше 2 МБ кусками (`/uploads/sessions/…`) с
   продолжением после обрыва связи — при желании это можно перенести (`web_app/js/media/chunk-upload.js`).
7. **Сжатие перед отправкой.** Сайт и телефон сжимают фото и видео до отправки. Если
   приложение шлёт исходники, их сожмёт сервер по тем же правилам — результат будет тем же,
   но загрузка сервера выше. Перенос сжатия на ПК — отдельная задача.

## 5. Новое на сервере, чего нет в ПК-версии

| Что | Адреса | Опора в `web_app` |
|---|---|---|
| Проекты: список с колонками по создателям, окно проекта, разделы «Договоры / Фото / Проект / Сдача», задачи проекта, завершение и «Активные / Архивные» | `/projects…` | `js/views/projects.js` |
| Склад проекта | `/warehouse…` | `js/views/warehouse.js` |
| Оборудование | `/equipment…` | `js/views/equipment.js` |
| Журнал изменений задачи, склада и оборудования (одно окно) | адреса — как их вызывает `web_app/js/views/task-view.js` | `js/core/journal.js` |
| Завершение задачи через подтверждение директора | `/tasks/{id}/completion`, `…/approve`, `…/decline` | `js/views/task-view.js` |
| Личные настройки на сервере | `/preferences` | `js/core/store.js` |
| Мессенджер: группы файлов, пересылка части группы (`file_ids`), удаление файла из группы, реакции, медиа чата | `/chat/grouped-message`, `/chat/message/{id}/forward` | `js/views/messenger.js`, `chat/chat.js` |

Для сайта задачи берутся из `/tasks/light`; настольное приложение может остаться на `/tasks`.

## 6. Настройки пользователя

Тема и масштаб хранятся на сервере отдельно для компьютера и телефона:
`web.settings.pc` и `web.settings.mobile`; прежний общий ключ `web.settings` читается,
пока устройство не сохранило своё. ПК-версии стоит читать и писать `web.settings.pc`:
тогда тема и масштаб совпадут с сайтом на компьютере.

## 7. Порядок работы

1. Переключить приложение на сервер beta 3 (разделы 2 и 4) и пройти основные сценарии:
   вход, задачи, файлы, мессенджер.
2. Добавить обработку ответов 403/409/400 с показом `detail` и замки на кнопках (раздел 3).
3. Перенести новые разделы (раздел 5) по образцу `web_app`.
4. Подключить автотесты: папка `project\pc` в модуле `kovapp_autotest` зарезервирована под ПК-версию.
