# Аудит безопасности мобильной версии Kovapp

Дата: 25.09.2026. Проверены приложение для Android (`mobile/`), надстройка
над веб-интерфейсом (`mobile/overlay/`) и новый серверный модуль
уведомлений (`server/server_app/native_push.py`,
`server/server_app/routers/native_push.py`).

Автоматическая проверка правил — `python mobile/tools/security_check.py`:
**45 правил, нарушений нет**. Ниже — что именно защищено, от кого, и что
остаётся на вашей стороне.

---

## От кого защищаемся

Чтобы оценивать защиту, сначала нужно назвать, кто может навредить:

1. **Посторонний в той же сети** — общий Wi-Fi в кафе, гостинице, на
   объекте. Может перехватывать и подменять трафик.
2. **Другое приложение на том же телефоне** — например, заражённая игра.
   Может пытаться вызвать части нашего приложения или прочитать его файлы.
3. **Тот, кто получил телефон в руки** — потерянный или переданный другому
   сотруднику телефон.
4. **Посредник доставки уведомлений** — Google (FCM). Честный, но видеть
   содержимое переписки ему незачем.
5. **Страница внутри приложения** — если в интерфейс когда-нибудь попадёт
   вредный скрипт (XSS), он не должен получить доступ к телефону.

## 1. Связь с сервером

| Мера | Что даёт |
|---|---|
| Рабочая сборка работает **только по HTTPS**; адрес с `http://` останавливает сборку | трафик шифруется, подменить сервер нельзя |
| Доверие **только системным сертификатам** | сертификат, установленный пользователем или вредоносной программой, не принимается |
| Ошибка сертификата **никогда не пропускается** (`handler.cancel()`, нет `proceed`) | «зелёного замка» не нарисовать поддельным сертификатом |
| Канал уведомлений (`wss://`) сверяет имя сервера с сертификатом | та же защита для постоянного соединения |
| HTTP разрешён только **отладочной** сборке и только к `localhost`/эмулятору | проверка на ПК удобна, а рабочая сборка «дыры» не получает |
| Свой сертификат (`serverCertificate`) действует **только для вашего адреса** | самоподписанный сертификат не ослабляет проверку других сайтов |

*Простыми словами:* HTTPS — это конверт, который по дороге никто не
вскроет. Проверка сертификата — это проверка, что конверт отдали именно
вашему серверу, а не тому, кто встал посередине. Приложение делает обе
проверки строже браузера: оно не даёт человеку нажать «всё равно
продолжить».

## 2. Данные на телефоне

| Мера | Что даёт |
|---|---|
| Вход хранится так же, как в браузере (память страницы), — в закрытой папке приложения | другие приложения его не прочитают |
| **Резервные копии и перенос на новый телефон выключены** | вход и ключи не уедут в облако и на чужой телефон |
| Секрет устройства и ключ шифрования уведомлений зашифрованы ключом **Android Keystore** | ключ хранится в защищённом хранилище телефона и не извлекается из него |
| **Выход из учётной записи** отвязывает телефон на сервере, стирает секреты, временные файлы и уведомления | телефон, отданный другому сотруднику, не получает чужих уведомлений |
| Телефон сверяет получателя уведомления (`uid`) | даже уведомление «в пути» не покажется новому владельцу |
| На заблокированном экране уведомление **без текста** («Новое сообщение») | переписку не прочитать с экрана блокировки |
| Временные файлы — со случайными именами (128 бит), стираются при запуске и выходе | их нельзя угадать и они не копятся |

## 3. Страница внутри приложения

Главный риск любого приложения на WebView — «мост» между страницей и
телефоном: через него скрипт может получить больше, чем сайт в браузере.

| Мера | Что даёт |
|---|---|
| Мост построен на `WebMessageListener`; **`addJavascriptInterface` не используется** | страница не видит Java-объекты приложения |
| Мост доступен **только главной странице вашего сервера** — Android сам сообщает источник сообщения | чужой сайт или встроенный фрейм мост не получит |
| Каждая команда проверяет аргументы | нельзя передать «кривые» данные |
| Доступ к файлам телефона — **только к выбранным самим человеком** (метка 128 бит) | скрипт не прочитает галерею или загрузки |
| Токен входа отдаётся **только своему серверу**; скачивание — только со своего сервера | токен не утечёт на посторонний адрес |
| Политика безопасности содержимого (CSP) **та же, что у сервера** | правила для скриптов в приложении не мягче, чем на сайте |
| Адреса `file://` и `content://` для страницы закрыты; смешанный HTTP-контент запрещён | страница не прочитает файлы телефона по адресу |
| Геопозиция, камера и микрофон странице не выдаются | всё это — только через системные окна по действию человека |
| Внешние ссылки — только `http(s)`, `mailto`, `tel`, открываются во внешнем браузере | ссылка не запустит чужое приложение с опасными параметрами |
| Отладка страницы (`chrome://inspect`) включена **только в отладочной сборке** | в рабочей сборке к странице не подключиться с ПК |
| Инструменты для ПК (симулятор, эмулятор моста) в APK не входят | ослабления для проверки на ПК не попадают на телефон |

## 4. Другие приложения на телефоне

| Мера | Что даёт |
|---|---|
| Снаружи доступен **только значок запуска**: службы, приёмник событий и провайдер файлов закрыты (`exported="false"`) | другое приложение не вызовет наши части |
| Провайдер снимков камеры выдаёт файл **по разовому разрешению** и не выпускает за свою папку | камера пишет только в свой файл |
| Переходы из уведомлений — **неизменяемые** (`FLAG_IMMUTABLE`), адрес внутри проверяется (только `#/…`) | подделать переход нельзя |
| Разрешения — **только нужные**: интернет, уведомления, работа в фоне, «Загрузки» (Android 9 и старше) | нет доступа к контактам, геопозиции, камере, микрофону |

## 5. Уведомления

**Через Google (FCM).** Текст шифруется ключом каждого телефона
(AES-256-GCM), в Google уходит только шифртекст — без заголовка и текста
уведомления. Даже ключ склейки уведомлений одного чата — не «chat-12», а
хеш метки с ключом телефона: Google не узнает номер чата. Видно ему лишь
то, что телефону пришло «что-то» и когда.

**Собственный канал.** Соединение шифруется TLS. Телефон входит в канал по
секрету устройства (256 бит). Сервер хранит только хеш секрета, как пароль,
и сравнивает его за постоянное время — подобрать секрет по времени ответа
нельзя. Чужой секрет — отказ и закрытие соединения. Очередь для
телефона, который офлайн, ограничена (100 уведомлений, срок хранения как у
Web Push), поэтому переполнить память сервера нельзя.

## 6. Новый серверный модуль

| Мера | Что даёт |
|---|---|
| Регистрация и отвязка телефона — **только после входа** | нельзя привязать свой телефон к чужой учётной записи |
| Номер устройства проверяется по формату (32 знака) | мусор в базу не попадает |
| Телефон, перешедший к другому сотруднику, получает новые секрет и ключ; очередь прежнего владельца стирается | старые уведомления новому владельцу не приходят |
| Не больше 10 телефонов на сотрудника (старые забываются) | таблица не разрастается |
| Привязка действует не дольше срока входа + сутки после последнего входа на телефоне | потерянный телефон перестаёт получать уведомления сам |
| Секреты и токены **не передаются в адресе** и не пишутся в журнал | не оседают в журналах nginx |
| Ключ сервисного аккаунта Firebase читается из файла вне кода | ключ не попадает в git и архивы |

Проверка: `python -m server.tests.native_push_tests` (42 проверки) —
шифрование, обмен с Google, очередь, протокол канала, а также то, что Web
Push после добавления модуля отправляет ровно то же, что раньше.

## 7. Найдено и исправлено при проверке

- **Скачивание файлов, собранных страницей**, не работало бы в APK: надстройка
  читала `blob:`-адрес запросом, а политика сервера (`connect-src 'self'`)
  это запрещает. Теперь данные берутся из самого объекта файла. Поймано
  UI-тестом.
- **Ключ склейки уведомлений** уходил в Google открытым текстом — заменён
  хешем (раздел 5).
- **Привязка потерянного телефона** жила бы бессрочно (смена пароля её не
  снимает) — теперь она ограничена сроком входа + сутки (раздел 8, пункт 5).
- **Строка журнала со словом «token»** переформулирована (в ней был только
  текст ошибки, но так понятнее при чтении журналов).
- Исправления 25.09.2026 (`docs/changes-2026-09-25.md`) проверены тестами на
  вашем коде; для безопасности важно первое: посторонний больше не может
  отправить файлы в чужую группу и получает отказ **до** приёма файлов.

## 8. Что остаётся на вашей стороне

1. **Ключ подписи APK** (`kovapp-release.jks`) — храните копию вне
   компьютера (зашифрованная флешка, сейф). Потеря ключа = невозможность
   обновить приложение у людей.
2. **Сертификат HTTPS** — если это Let's Encrypt, проверьте, что продление
   автоматическое (`certbot renew` по расписанию). Просроченный сертификат
   приложение не примет — оно не даст «продолжить».
3. **Ключ Firebase на сервере** — права только для пользователя сервера:
   `chmod 600 fcm-key.json`; в git и архивы не класть.
4. **Срок действия входа** — сейчас 7 суток (`ACCESS_TOKEN_EXPIRE_MINUTES`).
   Для телефонов, которые могут потеряться, можно сократить; выход из
   учётной записи и так отвязывает телефон сразу.
5. **Потерянный телефон.** Привязка телефона к сотруднику действует не
   дольше срока входа плюс сутки (сейчас 8 суток) после последнего входа в
   приложение на этом телефоне — дальше уведомления прекращаются сами.
   Смена пароля сама по себе привязку не снимает (так же и у браузерных
   подписок). Чтобы остановить уведомления сразу, выполните в базе:
   `DELETE FROM native_push_devices WHERE user_id = <номер сотрудника>;`
   — при удалении сотрудника привязки удаляются автоматически.
6. **Телефоны с root-доступом** — на них владелец может прочитать данные
   любых приложений, как и данные браузера. Если это недопустимо, это
   вопрос правил компании, а не приложения.
7. **Установка не из магазина** — Android и Play Protect покажут
   предупреждение. Это нормально для приложений, которые раздаются файлом.
8. **Обновления WebView** — на старом движке приложение само попросит
   обновиться (минимум версия 90).
